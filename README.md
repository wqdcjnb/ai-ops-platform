# AI 运营平台

面向电商运营团队的 AI 接入与用量管理方案。项目计划通过统一网关为每位成员发放独立 API Key，并按人员、用途和模型管理权限、额度与调用记录。

## 当前阶段

仓库目前处于原型开发与基础真实化阶段。需求、架构、安全规则、UI 方案与验收标准已经建立；运营控制台已具备“统一入口”本机只读版、“运营总览”演示数据版，以及人员、人员详情、Key 管理、额度与限流、用途与路由、模型与渠道、上游账号、用量与日志、告警中心、审计日志、对话审计和系统设置演示只读版；员工端已具备独立的本人自助演示页。BFF 已能分别探测 BFF、New API、CPA 与文档中心状态，并已接入最小登录、HttpOnly 会话和服务端 RBAC；业务指标、员工档案、管理配置和权限数据尚未映射到平台数据库或 New API 管理接口。文档中标注为“待验证”或“计划开发”的能力不代表已经实现。

已确认的方向：

- 客户端：Codex Desktop、WorkBuddy
- 统一管理：New API
- 正式上游：官方 API
- 实验上游：CLIProxyAPI（CPA），只用于隔离测试
- 本机测试数据库：SQLite
- 管理界面：Vue 3、TypeScript、Vite、Tabler、Pinia、ECharts
- 首批试点：5–10 名运营人员


## 业务应用依赖

前端与 BFF 使用 npm workspaces 管理。首次安装：

```powershell
npm.cmd ci
```

目录分别为 `apps/web` 和 `apps/server`。前端已实现统一入口、运营总览、人员、人员详情、Key 管理、额度与限流、用途与路由、模型与渠道、上游账号、用量与日志、告警中心、审计日志、对话审计、系统设置及员工自助原型；BFF 已提供 `/health`、认证、平台状态、数据库状态与任务接口、只读总览、人员、Key、额度、路由、模型、渠道、上游账号、用量、告警、操作审计、对话审计、系统设置和员工本人数据系列接口，以及 New API 状态接口。统一入口、上游账号及系统设置页的服务连通性来自实时探测；平台 SQLite 已建立核心表和迁移层，但业务数据、员工档案和管理配置当前仍是经过契约校验的演示数据，Key 只返回掩码，模型价格及调用成本明确区分官方实际、平台估算与 CPA 估算，上游账号和系统设置只返回凭据配置/验证状态，不返回凭据值。调用日志固定不返回对话正文，告警详情固定不返回上游完整正文，操作审计只记录字段级摘要且不提供删除入口；对话审计列表不含正文，原因门禁后也只返回预先脱敏的合成内容，并固定标记为未解密、未持久化访问审计。员工自助页使用独立布局，当前会话已通过服务端员工 RBAC，只展示演示数据范围内的掩码 Key、本人用量、业务模型别名、客户端连接说明和稳定错误码帮助，不返回完整 Key、其他人员、供应商、实际模型或上游渠道。管理写操作、对话采集、硬额度和数据导出固定关闭，员工临时额度申请保持禁用，正式与 CPA 实验路由固定禁止跨组回退。New API 管理数据、账号持久化仓储、真实告警采集、独立对话审计存储、真实审计追加写入、设置持久化与 CPA 管理认证尚未接入。依赖用途和验证结果见[依赖基线](docs-site/content/technical/dependency-baseline.md)。

运行运营总览需要两个终端：

```powershell
# 终端 1：BFF，监听 127.0.0.1:4175
npm.cmd run dev:server

# 终端 2：Vue 页面，监听 127.0.0.1:4174
npm.cmd run dev:web
```

访问 <http://127.0.0.1:4174>。前端通过开发代理访问 BFF，不在浏览器中保存管理凭据。

New API 默认探测 `http://127.0.0.1:3000`。如需验证管理连接，参照 `apps/server/.env.example` 在启动 BFF 的服务端环境中设置 `NEW_API_ACCESS_TOKEN`；旧版 New API 如需用户标识头，可同时设置 `NEW_API_USER_ID`。状态接口只返回连接状态，不返回凭据或上游响应正文。

## 安全边界

本仓库是公开仓库，不得提交以下内容：

- 官方 API Key、个人 Bearer Key、CPA 管理密钥
- OAuth Token、认证文件、浏览器登录信息
- 数据库文件、备份、运行日志和客户业务数据
- 包含密码或密钥的 `.env`、Compose 覆盖配置和截图

员工只接触 New API 地址及个人 Key。CPA、官方 API Key和 OAuth 凭据由管理员单独保管。

## 项目状态

15 个规划页面目前都已有可运行原型，最小登录、会话和服务端 RBAC 已完成，平台 SQLite 核心迁移层已建立。下一阶段将把账号/组织仓储接入数据库，并推进 New API 管理数据适配；各页面在真实数据、持久化和完整权限范围验收前仍维持“部分完成”。进度以[页面功能设计与完成表](docs-site/content/technical/page-functional-design.md)、[项目待办](docs-site/content/records/todo.md)和[方案决策](docs-site/content/records/decisions.md)为准。
