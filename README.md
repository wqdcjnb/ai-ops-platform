# AI 运营平台

面向电商运营团队的 AI 接入与用量管理方案。项目计划通过统一网关为每位成员发放独立 API Key，并按人员、用途和模型管理权限、额度与调用记录。

## 当前阶段

仓库目前处于原型开发与基础真实化阶段。需求、架构、安全规则、UI 方案与验收标准已经建立；运营控制台已具备“统一入口”本机只读版、“运营总览”演示数据版，以及人员、人员详情、Key 管理、额度与限流、用途与路由、模型与渠道、上游账号、用量与日志、告警中心、审计日志、对话审计和系统设置演示只读版；员工端已具备独立的本人自助演示页。BFF 已能探测基础服务，并已接入 SQLite、密码摘要登录、仅保存哈希的持久化会话、HttpOnly + SameSite=Strict Cookie、CSRF 校验和服务端 RBAC；人员、Key、月度软目标、调用元数据、告警事件/规则与审计事件已读取平台数据库。模型与渠道支持默认模拟模式和管理员主动切换的 New API 只读配置目录；当前真实目录为空，非空字段映射通过模拟接口验证。真实用量、健康指标、计费与完整生产权限仍待验收。文档中标注为“待验证”或“计划开发”的能力不代表已经实现。

已确认的方向：

- 客户端：Codex Desktop、WorkBuddy
- 统一管理：New API
- 正式上游：官方 API
- 实验上游：CLIProxyAPI（CPA），只用于隔离测试
- 本机测试数据库：SQLite
- 管理界面：Vue 3、TypeScript、Vite、Tabler、Pinia、ECharts
- 首批试点：5–10 名运营人员

```text
Codex Desktop / WorkBuddy
          │ 每人独立 API Key
          ▼
       New API
   ┌──────┴────────┐
   ▼               ▼
官方 API 渠道    CPA 实验渠道
正式业务          Pro OAuth 隔离测试
```

## 业务应用依赖

前端与 BFF 使用 npm workspaces 管理。首次安装：

```powershell
npm.cmd ci
```

目录分别为 `apps/web` 和 `apps/server`。前端已实现统一入口、运营总览、人员、人员详情、Key 管理、额度与限流、用途与路由、模型与渠道、上游账号、用量与日志、告警中心、审计日志、对话审计、系统设置及员工自助原型；BFF 已提供 `/health`、认证、平台状态、数据库状态与任务接口、只读总览、人员、Key、额度、路由、模型、渠道、上游账号、用量、告警、操作审计、对话审计、系统设置和员工本人数据系列接口，以及 New API 状态和管理能力状态接口。统一入口、上游账号及系统设置页的服务连通性来自实时探测；平台 SQLite 已建立核心表和迁移层，演示管理员/员工账号已落库并通过密码摘要校验，同时初始化了组织、用户、掩码 Key、软额度、调用元数据和审计模拟数据；会话与 CSRF 令牌只以哈希形式写入 SQLite，浏览器通过 HttpOnly + SameSite=Strict 会话 Cookie 和 CSRF 请求头完成受保护写操作校验；人员页面已读取 SQLite 人员/部门列表，并开放管理员添加本地演示人员；Key 页面已读取 SQLite Key 摘要，并支持管理员本地创建、一次性查看完整 Key；上述两类本地创建会与字段级审计摘要在同一 SQLite 事务中提交，完整 Key 与初始密码不写入审计；额度页面已读取 SQLite 月度软额度目标，审计页面已读取 SQLite 审计事件，用量与日志页面已读取 12 条可重复生成的模拟调用元数据，其他周期计量和未落库页面仍明确标记为演示数据。New API 管理认证已在本机验证；模型与渠道新增白名单只读映射、完整分页、30 秒配置缓存和显式来源切换。页面默认使用 4 个模型、5 个渠道的模拟目录；New API 空列表或失败不会自动填入演示数据，价格、健康与环境等缺失字段显示未知。模型示例价格不作为真实报价，调用成本口径区分官方实际、平台估算与 CPA 估算，上游账号和系统设置只返回凭据配置/验证状态，不返回凭据值。调用日志固定不返回对话正文，告警详情固定不返回上游完整正文，操作审计只记录字段级摘要且不提供删除入口；对话审计列表不含正文，原因门禁后也只返回预先脱敏的合成内容，并固定标记为未解密、未持久化访问审计。员工自助页使用独立布局，当前会话已通过服务端员工 RBAC，只展示演示数据范围内的掩码 Key、本人用量、业务模型别名、客户端连接说明和稳定错误码帮助，不返回完整 Key、其他人员、供应商、实际模型或上游渠道。除本地演示人员和 Key 创建外，高风险管理写操作、对话采集、硬额度和数据导出继续关闭，员工临时额度申请保持禁用，正式与 CPA 实验路由固定禁止跨组回退。New API 非空业务数据联调、人员/Key/真实日志映射、实时额度/用量账本、真实告警采集、独立对话审计存储、真实审计追加写入、设置持久化与 CPA 管理认证尚未完成。依赖用途和验证结果见[依赖基线](docs-site/content/technical/dependency-baseline.md)。

告警中心当前从 SQLite 读取 8 条可重复模拟事件与 8 条只读规则；事件详情只保留脱敏摘要和关联请求 ID，通知发送、规则编辑、确认、关闭与静默操作均保持关闭。真实告警采集和通知将在后续独立验收。

对话审计继续使用不含真实正文的合成数据。查看合成轮次时，SQLite 仅持久化操作者、目标、请求 ID、时间、是否已填写原因及原因长度；原因原文、认证信息、完整 Key 和真实对话正文均不保存。独立采集、加密、真实访问审计、到期清理和高风险内容操作仍未接入。

系统设置中的业务口径和五项高风险功能开关已从 SQLite 读取可重复的模拟配置，并在页面标记为 SQLite 来源；它们仍为只读，未开放设置编辑、凭据写入、连接验证、备份下载或恢复演练。组织、留存与备份状态继续明确标记为演示或未验证数据。

系统设置中的公司、部门、人员与五类角色目录也已由 SQLite 模拟组织聚合展示；真实组织同步、角色授权与高权限变更审计仍待单独验收。

调用元数据、对话审计正文、操作审计和导出文件的留存期限也已由 SQLite 模拟策略读取；这不包含任何自动清理或删除能力，清理任务、到期证明与恢复流程均未启用。

系统设置的备份状态已由 SQLite 安全元数据读取，并在数据库约束中固定为“未配置、无备份记录、禁止浏览器下载”；不会创建备份文件或执行恢复操作。

员工自助页的本人资料、掩码 Key 和用量现按已认证员工 ID 从 SQLite 模拟数据读取；模型别名目录仍明确标为 DEMO。该范围不返回其他人员、完整 Key、供应商、实际模型、上游渠道或管理配置，也不代表已经完成与真实网关账本的对接。

运营总览的五项指标、7/30 天趋势、人员排行、渠道摘要和告警摘要现从 SQLite 模拟调用、额度与告警记录聚合，并在页面标记为“SQLite 模拟数据”。这些汇总不是实时网关健康检查、真实日志或供应商账单；完整 Key、实际模型、认证信息、成本金额和上游完整错误正文不会返回浏览器。

统一入口的待处理事项和“人员与 Key”入口摘要也从 SQLite 模拟告警和掩码 Key 聚合，可直接进入告警中心或 Key 管理；其数量与到期风险仅用于本地演示，不代表真实网关事件或正式凭据状态。

运行运营总览需要两个终端：

```powershell
# 终端 1：BFF，监听 127.0.0.1:4175
npm.cmd run dev:server

# 终端 2：Vue 页面，监听 127.0.0.1:4174
npm.cmd run dev:web
```

访问 <http://127.0.0.1:4174>。前端通过开发代理访问 BFF，不在浏览器中保存管理凭据。

New API 默认探测 `http://127.0.0.1:3000`。本地连接配置可参照 `apps/server/.env.example`，只将所需的 `NEW_API_BASE_URL`、`NEW_API_ACCESS_TOKEN` 写入 `apps/server/.env.local`；此文件已被 Git 忽略。`npm.cmd run dev:server` 和服务端 `npm.cmd run start` 会自动加载该文件，已有进程环境变量优先，修改后需要重启 BFF。请勿直接复制示例中的账号密码配置，以免影响本地演示账号。旧版 New API 如需用户标识头，可同时设置 `NEW_API_USER_ID`。状态接口只返回连接状态，不返回凭据或上游响应正文。

## 安全边界

本仓库是公开仓库，不得提交以下内容：

- 官方 API Key、个人 Bearer Key、CPA 管理密钥
- OAuth Token、认证文件、浏览器登录信息
- 数据库文件、备份、运行日志和客户业务数据
- 包含密码或密钥的 `.env`、Compose 覆盖配置和截图

员工只接触 New API 地址及个人 Key。CPA、官方 API Key和 OAuth 凭据由管理员单独保管。
