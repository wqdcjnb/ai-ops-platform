# 本地内部测试操作手册

::: warning 使用边界
本手册用于在个人电脑上验证 AI 运营平台的页面、权限和本地流程。当前版本默认使用本地 SQLite 演示数据，不是生产版。不要把正式员工资料、正式 API Key、真实对话正文或生产流量导入本项目。
:::

::: warning 当前本地模式
当前本地测试只开放超级管理员。`apps/server/.env.local` 使用 `AI_OPS_ADMIN_ONLY=true`，打开 4174 后由 BFF 自动创建本机管理员会话，不再显示登录页面；员工账号不再创建，也不能登录。
:::

::: warning 软额度已废弃
本地环境使用 `AI_OPS_SOFT_QUOTA_ENABLED=false`。额度页不再展示软目标、临时额度申请/审批或软额度告警；相关写接口会返回 `SOFT_QUOTA_DEPRECATED`。成本点数仍可作为本地用量统计查看，但不代表额度目标或供应商账单。
:::

## 1. 测试目标

本轮测试主要验证：

- 页面能否正常打开、刷新和切换路由。
- 超级管理员的登录、写操作、审计和数据清理流程是否正确。
- 人员、Key、额度、路由、告警、审计和设置的本地流程是否可用。
- 本地写操作是否需要确认、CSRF 和幂等编号，并产生审计记录。
- 搜索、筛选、空数据、无权限和服务异常提示是否清楚。
- 可选验证本机 New API 的模型/渠道只读目录。

## 2. 测试前准备

### 2.1 环境要求

- Windows 电脑。
- Node.js 22–24。
- npm 10 或更新版本。
- 项目目录：`D:\Project\ai-ops-platform`。
- 4174 端口用于业务前端；3000 端口用于可选的本机 New API；4173 端口用于文档中心。

首次安装依赖：

```powershell
cd D:\Project\ai-ops-platform
npm.cmd ci
cd docs-site
npm.cmd ci
cd ..
```

### 2.2 测试账号

服务端会从 `apps/server/.env.local` 读取管理员身份。当前单管理员模式下，浏览器不会要求输入账号密码，而是通过本机 BFF 自动创建管理员会话；如果没有覆盖默认值，管理员身份为：

| 账号 | 用途 |
| --- | --- |
| `admin` | 唯一的本地超级管理员流程和写操作 |

单管理员模式不读取或要求管理员密码。只有明确关闭 `AI_OPS_ADMIN_ONLY`、启用多账号兼容登录时，旧版密码配置才会生效。测试账号只用于本机，不能当作正式账号。

## 4. 推荐测试顺序

### 4.1 登录和权限

1. 打开 <http://127.0.0.1:4174>，确认自动进入统一入口页，不再出现登录界面。
2. 确认顶部显示超级管理员角色和会话状态。
3. 刷新页面，确认会话仍可用；员工登录流程当前不适用。

### 4.2 统一入口和总览

1. 打开 `/`，点击运营总览、人员与 Key、上游账号和待处理事项入口。
2. 检查 BFF、New API、CPA 的状态是分别展示的，不把没有来源的状态当成真实指标。
3. 打开 `/overview`，检查指标、趋势、人员排行和告警摘要。
4. 确认页面上的 `DEMO`、`SQLITE` 或 `UNVERIFIED` 标签没有被误认为实时生产数据。

### 4.3 人员与部门

1. 打开 `/people`，在搜索框输入关键词，确认停止输入后自动刷新结果。
2. 点击“添加人员”，创建一条本地测试人员记录。
   - 所属部门现在是可输入的部门名称；空库默认没有部门，填写后系统才在本地 SQLite 建立对应部门目录。
3. 刷新页面，确认人员仍存在，并进入人员详情。
4. 下载 CSV 模板，使用 1–2 条虚拟数据进行预检和批量导入；部门列填写名称即可，旧版“部门编号”表头仍可使用。
5. 在人员详情核对每个 Key 的用途和唯一绑定模型；需要其他模型时到 Key 管理创建新的 Key。软额度入口已废弃，不再调整月度目标。
6. 打开操作审计，确认能看到对应事件摘要。
7. 如需测试停用，使用虚拟人员；停用只影响本地 SQLite，并会回收其本地演示 Key。

> 当前自动化验收已覆盖添加人员和批量导入；测试使用显式隔离的演示数据库，不读取本机空库配置。

### 4.4 Key 管理

1. 打开 `/keys`，按人员、用途、模型和状态筛选。
2. 点击“创建 Key”，只选择虚拟人员和演示用途。
3. 记录完整 Key 只在成功响应中显示一次。
4. 关闭提示后重新打开详情，确认只显示掩码。
5. 测试轮换和停用，确认旧 Key 状态变化和审计事件。

本地 Key 不会同步到 New API，也不会使任何真实凭据失效。

### 4.5 额度与限流

打开 `/limits`，确认页面显示“软额度已废弃”，不再显示软目标、临时额度申请或额度告警入口；硬限流仍保持关闭。

### 4.6 路由、模型和上游

- `/routes`：调整本地超时、429、5xx 和重试策略，刷新页面后确认保存结果。
- `/models`：默认查看模拟目录；管理员可切换到 New API 数据；真实目录为空时应显示空状态。
- `/upstreams`：查看 BFF、New API 和 CPA 状态；模拟验证只写本地历史，不重新授权真实账号。

### 4.7 用量、告警和审计

1. `/usage`：按日期、人员、用途、模型、渠道和请求 ID筛选 12 条模拟调用。
2. 从告警详情跳转到用量页，确认请求 ID来源标签正确。
3. `/alerts`：确认或关闭一条本地模拟告警，填写虚拟说明，回溯操作审计。
4. 编辑一条本地告警规则，刷新后确认规则仍保留。
5. `/audit`：筛选刚才的操作，打开详情并导出脱敏 CSV。
6. 确认导出动作本身也会产生审计记录，文件中没有完整 Key、密码、正文或原因原文。

### 4.8 对话审计和系统设置

- `/conversation-audit`：只用超级管理员查看预先脱敏的合成记录；填写查看原因，确认访问历史产生；复制、导出和删除应保持关闭。
- `/settings`：创建业务口径草稿，预览差异，发布后再回滚；确认版本历史和审计记录可见。
- 员工自助入口已废弃，不执行 `/me` 员工登录测试。

## 5. 可选：只读验证本机 New API

如果只想验证 New API 的真实模型/渠道目录，可以在 `apps/server/.env.local` 配置：

```env
NEW_API_BASE_URL=http://127.0.0.1:3000
NEW_API_ACCESS_TOKEN=仅保存在本机的管理访问令牌
NEW_API_USER_ID=
```

说明：

- 项目使用 `Authorization: Bearer <令牌>` 访问 New API 管理接口。
- 管理员登录密码不能直接替代管理访问令牌。
- 令牌只在 BFF 读取，浏览器不会收到令牌。
- `/models` 的“New API 数据”只读模型和渠道目录。
- 人员、Key、用量、额度、告警和对话审计仍然读取本地 SQLite。
- 不要把令牌写进 Markdown、截图、Git 提交或聊天记录。

## 6. 数据库隔离、备份与恢复

### 6.1 推荐使用独立测试库

停止 BFF 后执行：

```powershell
Copy-Item `
  D:\Project\ai-ops-platform\apps\server\data\platform.sqlite `
  D:\Project\ai-ops-platform\apps\server\data\platform-local-test.sqlite
```

再在 `apps/server/.env.local` 增加：

```env
PLATFORM_DB_PATH=D:/Project/ai-ops-platform/apps/server/data/platform-local-test.sqlite
```

这样页面上的新增人员、Key、额度和告警处置不会污染默认演示库。

### 6.2 恢复到默认演示库

1. 停止 BFF。
2. 从 `apps/server/.env.local` 删除或注释 `PLATFORM_DB_PATH`。
3. 重新启动 BFF。

不要直接删除数据库文件；如需清空测试数据，先保留一份备份，再由开发脚本或数据库迁移重新初始化。

## 9. 本地测试结束标准

本地测试可以结束的标准是：

- 超级管理员自动进入、刷新和管理操作均符合预期；员工账号不创建、不开放登录。

## 10. 接入个人 New API 账号进行只读联调

### 10.1 可以测试什么

当前项目可以使用你个人 New API 管理账号的访问令牌，验证以下内容：

| 验证项 | 访问方式 | 是否写入 New API |
| --- | --- | --- |
| 管理地址可达 | BFF 服务状态 | 否 |
| 管理令牌有效 | `/api/integrations/new-api/management` | 否 |
| 模型目录 | `/api/models?source=new_api` | 否 |
| 渠道目录 | `/api/channels?source=new_api` | 否 |
| 模型/渠道字段映射 | `/models` 页面 | 否 |
| 人员、Key、额度、告警和审计 | 本地 SQLite 页面 | 不访问个人 New API 数据 |

因此，个人账号接入的准确含义是“读取个人 New API 的模型和渠道目录来验证适配器”，不是把个人账号的全部运营数据导入平台。

### 10.2 账号凭据要求

当前适配器使用管理访问令牌，不直接使用网页登录的用户名和密码。令牌需要能够访问 New API 的模型和渠道管理接口，服务端通过以下请求头发送：

```text
Authorization: Bearer <管理访问令牌>
```

如果你的 New API 部署还要求用户标识头，可以额外配置 `NEW_API_USER_ID`。不确定时先留空，收到 401/403 再向 New API 管理员确认。

### 10.3 配置个人账号

1. 确认 New API 在本机运行，并能打开 <http://127.0.0.1:3000>。
2. 停止 BFF 窗口，避免修改配置后旧进程继续使用旧令牌。
3. 打开 `apps/server/.env.local`，只在本机保存以下配置：

```env
NEW_API_BASE_URL=http://127.0.0.1:3000
NEW_API_ACCESS_TOKEN=你的个人管理访问令牌
NEW_API_USER_ID=
```

4. 确认该文件没有被 Git 追踪，也不要把它复制到文档、截图或压缩包中。
5. 重新启动 BFF 和前端。

### 10.4 浏览器联调步骤

1. 以本地 `admin` 演示账号登录 <http://127.0.0.1:4174>。
2. 打开“统一入口”，确认 New API 状态不再显示“未配置”。
3. 打开“模型与渠道”。
4. 点击“New API 数据”来源按钮。
5. 记录页面显示的来源、检查时间、模型总数和渠道总数。
6. 打开任意模型或渠道详情，确认没有完整管理令牌、渠道密钥或上游响应正文。
7. 切换回“模拟数据”，确认模拟目录和 New API 目录没有混合显示。
8. 刷新页面，再次切换到 New API 数据，验证 30 秒缓存和失败重试行为。

### 10.5 结果如何判断

| 页面状态 | 含义 | 下一步 |
| --- | --- | --- |
| `ready`，模型和渠道数量大于 0 | 令牌有效，目录读取成功 | 抽查名称、状态和分页映射 |
| `ready`，模型和渠道数量为 0 | 连接和鉴权成功，但当前账号/实例没有可读取目录 | 先在 New API 后台确认目录是否为空，不要把空列表当作系统故障 |
| `auth_required` | 令牌未配置、过期或权限不足 | 更换只读管理令牌，重启 BFF |
| `unavailable` | 地址不可达、接口异常或返回格式不兼容 | 先检查 3000 端口和 New API 日志，再看版本适配 |
| 页面仍显示模拟数据 | 前端仍在 `demo` 来源，或 BFF 未重启 | 重启 BFF 后重新点击 New API 数据 |

本机最近一次只读联调结果为：New API 管理接口 `ready`，模型和渠道接口均可访问，但返回数量为 0。这表示适配器连接成功，当前 New API 目录为空或该账号没有目录数据，不表示项目读取到了真实模型配置。

### 10.6 不要在个人账号上执行的操作

在当前版本中，不要为了测试点击或调用以下真实操作：

- 创建、停用或轮换 New API 真实 Key。
- 修改 New API 渠道、模型、价格、余额或用户权限。
- 修改真实额度、硬限流或路由配置。
- 发起真实批量导入、真实员工同步或真实日志回灌。
- 把 New API 的真实对话正文复制到本地 SQLite。

平台页面里的“创建 Key”“停用”“轮换”“调整额度”“编辑规则”等按钮只操作本地演示数据库；这与 New API 个人账号的真实写操作是两套系统，不要把两者混淆。

## 12. 权限测试矩阵

### 12.1 管理员测试

使用 `admin` 账号：

1. 可以查看管理端所有页面。
2. 可以创建本地人员和本地 Key。
3. 可以编辑本地路由和告警规则；软额度写操作已废弃。

### 12.3 失败结果记录

如果出现非超级管理员账号能够登录、读取管理数据或修改管理配置，应立即停止测试，记录页面地址、时间和请求 ID，不要继续操作或传播响应内容。

## 13. 故障排查

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| `4174` 打不开 | 前端未启动或端口被占用 | 重新执行 `npm.cmd run dev:web`，检查窗口输出 |
| 页面显示 BFF 不可用 | 4175 服务未启动 | 执行 `npm.cmd run dev:server`，确认端口 4175 |
| New API 显示未配置 | `.env.local` 没有令牌或变量为空 | 只在本地补充 `NEW_API_ACCESS_TOKEN` 后重启 BFF |
| New API 显示认证失败 | 令牌过期、权限不足或需要用户头 | 更换管理令牌，必要时设置 `NEW_API_USER_ID` |
| New API 显示不可达 | 3000 端口关闭、地址错误或 Docker 未启动 | 先打开 <http://127.0.0.1:3000>，再检查 `NEW_API_BASE_URL` |
| 模型和渠道数量为 0 | New API 目录为空或账号无权限读取 | 到 New API 后台确认目录，不要回退猜测数据 |
| 切换来源后旧数据仍显示 | BFF 未重启或前端缓存 | 重启 BFF，刷新页面后重新选择来源 |
| 写操作返回 401/403 | 未登录、角色不足或会话过期 | 重新登录正确角色，不要绕过服务端权限 |
| 写操作返回 CSRF 错误 | Cookie 与请求头不一致 | 刷新页面重新获取会话，不要关闭 CSRF 校验 |
| SQLite 被占用 | 另一个 BFF 或脚本仍在使用数据库 | 停止旧 BFF，再使用独立 `PLATFORM_DB_PATH` |
| 浏览器 E2E 失败 | 测试服务未启动、端口被占用或测试环境变量被覆盖 | 先确认 Playwright 使用隔离端口和 `AI_OPS_ADMIN_ONLY=false`，再重跑单条流程 |

## 14. 停止个人账号联调与回滚

完成个人账号只读测试后：

1. 停止 BFF 和前端。
2. 从 `apps/server/.env.local` 删除 `NEW_API_ACCESS_TOKEN`，或改为空值。
3. 如果使用独立测试数据库，保留它作为测试证据；不要把它上传到 GitHub。
4. 重新启动 BFF，确认页面回到“未配置/模拟数据”状态。
5. 如果需要恢复默认演示库，移除 `PLATFORM_DB_PATH` 覆盖即可。
6. 如果个人令牌曾经在聊天、截图或日志中出现，应立即在 New API 中撤销并重新创建。

```powershell
cd D:\Project\ai-ops-platform\apps\server

```

检查脚本必须显示以下结果：

- `AI_OPS_ADMIN_ONLY=true`、`AI_OPS_SEED_DEMO_DATA=false`、`AI_OPS_SOFT_QUOTA_ENABLED=false`。
- 认证没有被关闭，SQLite 主文件存在。
- 4174/4175 端口如果已经启动则显示 `PASS`；尚未启动时显示 `WARN`，不代表配置失败。
- BFF `/health` 和 `/gateway/health` 可访问时显示 `PASS`。

备份目录默认位于 `apps/server/data/backups/platform-YYYYMMDD-HHmmss`，其中包含 `platform.sqlite`、运行中的 WAL/SHM（若存在）和 `manifest.json`。清单只含文件大小与哈希，不含任何环境变量或令牌。

发布启动顺序：

1. 确认 `preflight:local` 通过并保留本次备份目录路径。
2. 在一个窗口执行 `npm.cmd run dev:server`，在另一个窗口执行 `npm.cmd run dev:web`。
3. 打开 <http://127.0.0.1:4174>，只用超级管理员和虚拟数据进行测试。
4. 完成测试后按 `Ctrl+C` 停止两个进程；不要在服务运行时复制或替换 SQLite 文件。

回滚原则：先停止 BFF，再把当前数据库文件移动到一个新的、明确命名的隔离目录，确认备份目录和 `manifest.json` 后，由负责人手工复制需要恢复的 SQLite/WAL/SHM 文件；恢复后重新执行 `preflight:local`。本阶段不提供自动覆盖或删除命令，避免误删本机数据。

该交接只适合本机内部测试，不代表生产发布。生产备份加密、异地保存、恢复演练、真实客户端验收和多管理员权限仍属于二期规划。
