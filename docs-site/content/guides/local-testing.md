# 本地内部测试操作手册

::: warning 使用边界
本手册用于在个人电脑上验证 AI 运营平台的页面、权限和本地流程。当前版本默认使用本地 SQLite 演示数据，不是生产版。不要把正式员工资料、正式 API Key、真实对话正文或生产流量导入本项目。
:::

## 1. 测试目标

本轮测试主要验证：

- 页面能否正常打开、刷新和切换路由。
- 管理员、部门负责人、财务和员工的权限边界是否正确。
- 人员、Key、额度、路由、告警、审计和设置的本地流程是否可用。
- 本地写操作是否需要确认、CSRF 和幂等编号，并产生审计记录。
- 搜索、筛选、空数据、无权限和服务异常提示是否清楚。
- 可选验证本机 New API 的模型/渠道只读目录。

## 2. 测试前准备

### 2.1 环境要求

- Windows 电脑。
- Node.js 22–24。
- npm 10 或更新版本。
- 项目目录：`D:\Project\ai-ops-platform`。
- 4174 端口用于业务前端；3000 端口用于可选的本机 New API；4173 端口用于文档中心。

首次安装依赖：

```powershell
cd D:\Project\ai-ops-platform
npm.cmd ci
cd docs-site
npm.cmd ci
cd ..
```

### 2.2 测试账号

服务端会从 `apps/server/.env.local` 读取账号密码；如果没有覆盖默认值，本地演示账号为：

| 账号 | 默认密码 | 用途 |
| --- | --- | --- |
| `admin` | `admin-demo` | 管理员流程和写操作 |
| `employee` | `employee-demo` | 员工自助和临时额度申请 |

如果 `.env.local` 中设置了 `AUTH_ADMIN_PASSWORD` 或 `AUTH_EMPLOYEE_PASSWORD`，以本地配置为准。测试账号只用于本机，不能当作正式账号。

## 3. 启动顺序

### 3.1 启动业务 BFF

在第一个 PowerShell 窗口执行：

```powershell
cd D:\Project\ai-ops-platform
npm.cmd run dev:server
```

看到 Fastify 监听本机地址后保持窗口运行。

### 3.2 启动前端

在第二个 PowerShell 窗口执行：

```powershell
cd D:\Project\ai-ops-platform
npm.cmd run dev:web
```

打开：<http://127.0.0.1:4174>。

### 3.3 可选启动文档中心

在第三个 PowerShell 窗口执行：

```powershell
cd D:\Project\ai-ops-platform\docs-site
npm.cmd run dev
```

打开：<http://127.0.0.1:4173>。

### 3.4 停止服务

回到对应 PowerShell 窗口按 `Ctrl+C`。修改 `apps/server/.env.local` 后，必须重启 BFF 才会加载新配置。

## 4. 推荐测试顺序

### 4.1 登录和权限

1. 用 `admin` 登录，确认进入统一入口页。
2. 退出后用 `employee` 登录，确认只进入 `/me`，看不到管理侧栏。
3. 用员工账号直接访问 `/people`、`/keys` 和 `/audit`，确认被拦截或跳转到员工自助页。
4. 用管理员重新登录，确认顶部显示当前角色和会话状态。

### 4.2 统一入口和总览

1. 打开 `/`，点击运营总览、人员与 Key、上游账号和待处理事项入口。
2. 检查 BFF、New API、CPA 的状态是分别展示的，不把没有来源的状态当成真实指标。
3. 打开 `/overview`，检查指标、趋势、人员排行和告警摘要。
4. 确认页面上的 `DEMO`、`SQLITE` 或 `UNVERIFIED` 标签没有被误认为实时生产数据。

### 4.3 人员与部门

1. 打开 `/people`，在搜索框输入关键词，确认停止输入后自动刷新结果。
2. 点击“添加人员”，创建一条本地测试人员记录。
3. 刷新页面，确认人员仍存在，并进入人员详情。
4. 下载 CSV 模板，使用 1–2 条虚拟数据进行预检和批量导入。
5. 在人员详情调整模型白名单和月度软目标。
6. 打开操作审计，确认能看到对应事件摘要。
7. 如需测试停用，使用虚拟人员；停用只影响本地 SQLite，并会回收其本地演示 Key。

> 当前自动化验收在“保存人员”步骤仍有阻塞，人员流程可以先手工验收；不要把该步骤标记为自动化通过。

### 4.4 Key 管理

1. 打开 `/keys`，按人员、用途、模型和状态筛选。
2. 点击“创建 Key”，只选择虚拟人员和演示用途。
3. 记录完整 Key 只在成功响应中显示一次。
4. 关闭提示后重新打开详情，确认只显示掩码。
5. 测试轮换和停用，确认旧 Key 状态变化和审计事件。

本地 Key 不会同步到 New API，也不会使任何真实凭据失效。

### 4.5 额度与限流

打开 `/limits`，依次测试：

1. 折叠和展开公司、部门、人员、用途、Key 节点。
2. 调整虚拟人员的月度软目标。
3. 用员工账号申请临时额度，再用管理员批准或拒绝。
4. 验证申请到期后变为“已到期”。
5. 创建本地并发预留，分别执行结算、取消和重复提交。
6. 确认页面提示“软目标/演练”，不会阻断请求或修改网关额度。

### 4.6 路由、模型和上游

- `/routes`：调整本地超时、429、5xx 和重试策略，刷新页面后确认保存结果。
- `/models`：默认查看模拟目录；管理员可切换到 New API 数据；真实目录为空时应显示空状态。
- `/upstreams`：查看 BFF、New API 和 CPA 状态；模拟验证只写本地历史，不重新授权真实账号。

### 4.7 用量、告警和审计

1. `/usage`：按日期、人员、用途、模型、渠道和请求 ID筛选 12 条模拟调用。
2. 从告警详情跳转到用量页，确认请求 ID来源标签正确。
3. `/alerts`：确认或关闭一条本地模拟告警，填写虚拟说明，回溯操作审计。
4. 编辑一条本地告警规则，刷新后确认规则仍保留。
5. `/audit`：筛选刚才的操作，打开详情并导出脱敏 CSV。
6. 确认导出动作本身也会产生审计记录，文件中没有完整 Key、密码、正文或原因原文。

### 4.8 对话审计和系统设置

- `/conversation-audit`：只用超级管理员查看预先脱敏的合成记录；填写查看原因，确认访问历史产生；复制、导出和删除应保持关闭。
- `/settings`：创建业务口径草稿，预览差异，发布后再回滚；确认版本历史和审计记录可见。
- `/me`：用员工账号确认只能看到本人资料、掩码 Key、本人用量和临时额度申请。

## 5. 可选：只读验证本机 New API

如果只想验证 New API 的真实模型/渠道目录，可以在 `apps/server/.env.local` 配置：

```env
NEW_API_BASE_URL=http://127.0.0.1:3000
NEW_API_ACCESS_TOKEN=仅保存在本机的管理访问令牌
NEW_API_USER_ID=
```

说明：

- 项目使用 `Authorization: Bearer <令牌>` 访问 New API 管理接口。
- 管理员登录密码不能直接替代管理访问令牌。
- 令牌只在 BFF 读取，浏览器不会收到令牌。
- `/models` 的“New API 数据”只读模型和渠道目录。
- 人员、Key、用量、额度、告警和对话审计仍然读取本地 SQLite。
- 不要把令牌写进 Markdown、截图、Git 提交或聊天记录。

## 6. 数据库隔离、备份与恢复

### 6.1 推荐使用独立测试库

停止 BFF 后执行：

```powershell
Copy-Item `
  D:\Project\ai-ops-platform\apps\server\data\platform.sqlite `
  D:\Project\ai-ops-platform\apps\server\data\platform-local-test.sqlite
```

再在 `apps/server/.env.local` 增加：

```env
PLATFORM_DB_PATH=D:/Project/ai-ops-platform/apps/server/data/platform-local-test.sqlite
```

这样页面上的新增人员、Key、额度和告警处置不会污染默认演示库。

### 6.2 恢复到默认演示库

1. 停止 BFF。
2. 从 `apps/server/.env.local` 删除或注释 `PLATFORM_DB_PATH`。
3. 重新启动 BFF。

不要直接删除数据库文件；如需清空测试数据，先保留一份备份，再由开发脚本或数据库迁移重新初始化。

## 7. 自动化检查

在项目根目录执行：

```powershell
npm.cmd run typecheck
npm.cmd run test
npm.cmd run test:e2e --workspace @ai-ops/web
```

当前状态说明：

- 类型检查和单元/服务端流程测试用于确认接口和数据边界。
- Playwright 覆盖登录、人员、批量导入、Key、模型白名单、额度、告警和审计流程。
- 最近完整 E2E 在添加人员保存步骤阻塞，修复前不能把全量浏览器验收写成“全部通过”。

## 9. 本地测试结束标准

本地测试可以结束的标准是：

- 管理员和员工登录、退出、越权访问均符合预期。
- 人员、Key、额度、告警、审计和设置流程可以用虚拟数据重复操作。
- 每个写操作都能在审计页找到脱敏记录。
- 页面没有把 `DEMO`、`SQLITE` 或 `UNVERIFIED` 数据显示成生产数据。
- 真实 New API 测试只验证只读模型/渠道目录，不改变真实配置。
- 测试记录中没有保存任何真实密码、令牌、完整 Key 或对话正文。
