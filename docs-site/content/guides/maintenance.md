# 文档站使用与维护

## 启动

首次使用需安装 Node.js 22 或更新版本，以及可访问 npm 的网络。当前机器已具备 Node.js。

双击 docs-site 目录中的 `启动文档中心.cmd`。首次运行自动执行 `npm ci` 安装锁定依赖，然后启动本机预览。

访问 <http://127.0.0.1:4173>。保持窗口运行，按 Ctrl+C 停止。端口已被占用时不会切换到其他端口，也不会终止占用进程；已启动本站时可直接打开该地址。

```powershell
cd docs-site
npm.cmd ci
npm.cmd run dev
```

## 维护主版本

正式维护内容位于 `docs-site/content/`。后续在对话中提出修改，由助手更新对应 Markdown 和项目记录。此前 outputs 内的文件为历史交付件，不再双向自动同步。

编辑已有 Markdown 后，开发预览自动更新；顶部“下载 Markdown 原文”直接读取当前源文件。若采用构建后的静态站，每次内容变更需重新构建。

## 新增页面

1. 在 content 下相应分类新增 Markdown。
2. 将相对路径和中文标题添加到 `.vitepress/pages.mjs`，作为导航及下载白名单。
3. 更新相关入口和更新记录。
4. 执行检查、构建，再检查页面与搜索结果。

不要把整个部署目录放进 content。配置、凭据、运行日志、客户数据和数据库备份不属于文档内容。原文下载目录由程序生成，不手工编辑。

## 检查与构建

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run preview
```

构建产物位于 `.vitepress/dist/`，可独立静态部署。本阶段只绑定本机回环地址。对团队开放前需另行规划访问控制。

本地搜索在浏览器内执行，不把查询发送给第三方搜索服务。“常用入口”只维护 AI OPS 地址和内部依赖状态，不新增 New API/CPA 管理网站链接；后续部署变更需同步更新该页。
