# 中转站与AI OPS目录

## 1. 唯一员工可见模型

AI OPS 对员工、Codex、WorkBuddy 和标准 API 只暴露一个自定义虚拟模型：

~~~text
显示名：AI OPS
API ID：ai-ops
~~~

AI OPS不是某一个中转站的真实模型，也不是静态模型别名。它是平台根据请求的模态、能力、上下文、规格、实时健康度、队列和预算，在多个中转站原始模型之间做出受控选择的统一能力入口。

员工不会选择 provider-a、provider-b、图片模型或视频模型。员工只选择工作类型和参数，例如文本提问、生成图片、提交视频；API 的 model 字段始终使用 ai-ops。

## 2. 内外双层目录

~~~text
内部目录
  中转站 → 原始模型 → 能力验证 → AI OPS能力路由
                                           ↓
员工目录
  AI OPS（文本 / 代码 / 图片 / 视频 / 音频）
~~~

| 目录层 | 保存内容 | 可见对象 |
| --- | --- | --- |
| Provider | 中转站地址、认证引用、区域、状态 | 超级管理员和系统服务 |
| ProviderModel | 原始模型 ID、协议、真实能力、限制、健康度 | 超级管理员和适配器 |
| UnifiedCapability | AI OPS的一种能力，例如文本或视频 | 超级管理员、员工、客户端 |
| UnifiedRoute | 某个能力到原始模型的主备路由与策略 | 超级管理员和路由器 |
| PublicCatalog | 仅包含 ai-ops 和可用能力 | 员工、Codex、WorkBuddy、API |

## 3. AI OPS能力声明

AI OPS是一项聚合服务。它公开的能力必须由至少一条健康内部路由支撑。

| 能力 | 入口 | 内部路由必须验证的条件 |
| --- | --- | --- |
| 文本与代码 | Responses 或 Chat Completions | 流式、上下文窗口、工具调用、结构化输出 |
| 图片生成 | 图片端点 | 尺寸、宽高比、质量、参考图、输出格式 |
| 图片编辑 | 图片编辑端点 | 输入资产、蒙版、编辑能力、输出格式 |
| 视频 | 视频 job 端点 | 时长、尺寸、帧率、首尾帧、音频、取消与查询 |
| 音频 | 音频端点或 job | 文件类型、时长、语言、流式与结果格式 |

某种能力没有健康路由时，应从AI OPS的 capability 列表中暂时隐藏或标记为不可用；不能用其他模态假装替代。

## 4. 中转站接入流程

1. 超级管理员提交第三方账号名称、Base URL 和 API Key。
2. 服务端仅允许公共 HTTPS 地址，并拒绝本机、内网和保留地址；部署方可选配精确主机白名单进一步收紧范围。
3. 服务端自动尝试输入地址、`/v1`、`/api/v1` 与 `/api` 这些常见 API 根路径，并识别标准 `data`、常见 `models`、`items`、`results` 或直接数组目录；识别成功后保存实际可用的 API 根路径。
4. 管理员选择需要接入的模型；保存时会再次校验选择。
5. 管理员可对已选模型发起最小探测，记录可调用状态、目录确认状态和延迟。文本候选执行最小文本探测；从目录元数据或保守模型名识别出的图片、视频、语音模型不会自动创建可能计费的媒体任务。
6. 选定模型按内部模态候选组纳入 AI OPS 路由；文本、图片、视频、语音请求只选择对应组，同名模型在目录中合并来源。
7. 路由经健康验证、预算策略和灰度检查后发布到目录快照。

同步失败时，平台保留最后一个完整成功快照，标记同步过期并提醒管理员；不会让员工请求同步等待，也不会清空正在健康服务的AI OPS能力。

## 5. AI OPS路由契约

每条 UnifiedRoute 至少定义：

| 类别 | 字段 |
| --- | --- |
| 匹配条件 | capability、输入/输出模态、工具调用、结构化输出、尺寸、时长、上下文 |
| 候选 | provider_id、provider_model_id、区域、优先级、成本类别 |
| 性能 | TTFT 或队列延迟、最大并发、连接池与健康阈值 |
| 容错 | 重试条件、备用路线、熔断阈值、取消能力 |
| 预算 | 成本估算、预占单位、员工与组织并发限制 |
| 可观测 | 适配器版本、目录版本、最后验证时间、错误摘要 |

AI OPS在内部可以混合不同中转站和原始模型，但一次请求只会选择与当前请求条件语义兼容的一个实际执行路径。路由器不能因某一站点较快就用纯文本模型处理图片、用低规格视频模型处理不兼容的参数，或无提示删除工具调用。

## 6. 员工模型列表

员工请求 GET /v1/models 时，只得到AI OPS一项。典型公开字段：

~~~json
{
  "id": "ai-ops",
  "display_name": "AI OPS",
  "capabilities": ["text", "code", "image_generation", "video_generation", "audio"],
  "status": "active"
}
~~~

上游站点名、原始模型名、成本、路由权重和失败细节只在管理员控制台显示。API 可返回当前请求实际使用的能力类别和平台 request_id，但不应泄露中转站凭据或内部拓扑。

## 7. 路由切换

AI OPS允许跨中转站和跨原始模型切换，因为它本身是聚合模型；但切换的前提是能力契约匹配。

| 请求类型 | 允许的内部切换 |
| --- | --- |
| 普通文本 | 选择任何满足文本、上下文和流式条件的候选 |
| 代码工具调用 | 仅选择工具调用和所需输出语义兼容的候选 |
| 图片编辑 | 仅选择支持当前输入、编辑和尺寸参数的候选 |
| 视频 | 仅选择支持时长、规格、资产输入和 job 生命周期的候选 |
| 会话续接 | 仅选择能够接受会话服务重建后的上下文和附件引用的候选 |

若没有兼容候选，网关必须明确返回能力暂不可用或请求参数不受支持；不能静默降级成另一个类型的结果。

## 8. 目录发布与回滚

目录以版本化快照发布：

~~~text
catalog_version
  ├─ public: ai-ops capabilities
  ├─ internal: provider models and route candidates
  ├─ policies: budget, region, quality and fallback
  └─ health snapshot
~~~

每次请求在开始时绑定一个目录版本；请求中途的同步更新不能改变它的参数语义。管理员发布新路由时可灰度一小部分流量；异常时回滚到最近已验证快照。

## 9. 管理员检查清单

- 员工目录是否只显示AI OPS。
- 每项公开能力是否至少有一个已验证健康路由。
- 内部候选是否满足当前能力、参数、会话和取消要求。
- 中转站新增或失效是否只改变目录快照，不阻塞员工请求。
- AI OPS的图片、视频、音频能力是否按真实支持状态公开。
- 每次路由是否可通过 request_id 在管理员控制台追溯。
