# 页面功能设计与完成表

::: info 文档用途
本文是统一运营控制台的页面级功能设计、开发拆分和验收基线。内容依据更新版合并文档与[页面规划 V2](/technical/page-plan-v2)整理；“页面可打开”不等于功能完成，只有真实数据、权限、异常状态和验收证据同时具备才可标记完成。
:::

## 1. 页面数量

系统共规划 **15 个路由级页面**：

- 管理端 13 个一级页面。
- 管理端 1 个人员详情页，由人员列表进入，不占侧栏一级菜单。
- 员工端 1 个自助页面，使用独立布局。

| 编号 | 页面 | 路由 | 使用角色 | 优先级 |
| --- | --- | --- | --- | --- |

| P03 | 人员与部门 | `/people` | 超级管理员、管理员、部门负责人 | P1 |

| P06 | 额度与限流 | `/limits` | 超级管理员、管理员、部门负责人、财务只读 | P3 |

## 2. 公共功能设计

以下能力由全部页面共享，不重复计算为独立页面。

| 功能点 | 作用 | 实现方式 | 完成条件 |
| --- | --- | --- | --- |
| 登录与会话 | 确认当前用户身份，避免匿名访问管理数据 | BFF 使用安全 Cookie 会话；生产环境启用 HTTPS、`HttpOnly`、`Secure` 和 CSRF 防护 | 未登录访问受保护路由会跳转登录；会话过期有明确提示 |
| 角色权限 | 控制全局、本部门、本人及对话正文范围 | Vue Router `meta.roles` 只控制展示；BFF 对每个接口再次执行 RBAC 和数据范围过滤 | 越权接口测试全部返回 403，不能通过直接 URL 绕过 |
| 分组侧栏 | 让高频运营、配置和审计任务清晰分区 | Vue Router 路由表生成菜单；按角色过滤；移动端使用抽屉 | 当前页、折叠状态和移动端导航正常 |
| 全局搜索 | 快速查找人员、Key 掩码和请求 ID | 顶栏搜索调用 `/api/search`，结果按类型分组；不搜索对话正文 | 结果受角色和部门范围限制，不返回完整 Key |
| 服务状态 | 分别判断 BFF、New API 和 CPA 是否可用 | BFF 主动探测上游；前端显示独立状态、检查时间和重试 | 不再使用无来源的“4/5 可用”汇总 |
| 数据来源标签 | 防止把演示或未验证数据当成真实数据 | 响应统一返回 `LIVE / PARTIAL / DEMO / UNVERIFIED` 和生成时间 | 页面首屏持续可见，导出中同样保留来源 |
| 通用筛选 | 统一时间、部门、人员、模型、渠道和状态口径 | BFF 校验参数；筛选下拉框即时查询 | 当前筛选结果与汇总口径一致 |
| 关键词实时搜索 | 减少列表检索的额外操作 | 人员、Key、额度、路由、模型、上游、用量、告警、审计、对话审计的关键词输入均在停顿 240ms 后自动查询；“查询”和“清除”仍可立即执行 | 新输入取消等待中的旧查询；页面离开后不再触发查询 |
| 通用数据状态 | 处理加载、空数据、部分失败、无权限和首次配置 | 页面级状态组件；错误仅显示分类、请求 ID、时间和重试 | 不泄露管理密钥或上游完整错误正文 |
| 操作审计 | 追踪所有管理变更 | 写接口记录操作者、对象、变更前后摘要、来源和结果 | 写操作成功与失败都可按请求 ID 查询 |
| 响应式与可访问性 | 支持桌面高密度操作及移动查询 | Tabler 响应式布局；键盘焦点、语义标签、文字+图标状态 | 桌面、平板、手机核心流程可使用 |

## 3. 技术实现总览

```text
Vue 页面
  → Vue Router / Pinia / Zod 响应校验
  → Fastify BFF（会话、RBAC、审计、错误封装）
  → New API 适配器（人员、Key、模型、用量、日志）
  → CPA 适配器（实验账号、认证窗口、冷却与错误）
  → 平台数据库（组织扩展、用途、额度、告警、操作审计）
  → 独立审计存储（获准采集并加密的对话正文）
```

实现原则：

- 浏览器永远不直接访问 New API 或 CPA 管理接口。
- 上游返回先在 BFF 进行 Zod 校验和字段转换，页面只依赖平台自己的稳定对象。
- New API 缺少的部门、岗位、负责人、用途和多层额度字段保存在平台数据库，通过稳定 ID 映射，不直接修改转发内核。
- 调用元数据与对话正文分库存储；未开启采集的 Key 不保存正文。
- 所有列表统一使用 `{ items, page, pageSize, total }`，错误统一使用 `{ error: { code, message, requestId } }`。

## 4. 页面详细功能

### P01 统一入口

| 功能点 | 作用 | 页面表现 | 实现方式 |
| --- | --- | --- | --- |
| 四张业务入口卡 | 快速进入最常用任务 | 运营总览、人员与 Key、上游账号、待处理事项 | 聚合路由权限与摘要数据；点击进入对应页面 |
| 全局搜索 | 从任意管理页面快速定位对象 | 顶栏输入人员、Key 掩码或请求 ID，结果按类型分组，点击跳转对应详情/列表 | `GET /api/search?q=...` 读取 SQLite 摘要；240ms 防抖、角色/部门范围过滤；不搜索对话正文或返回完整 Key |
| 服务矩阵 | 判断基础组件是否在线 | BFF、New API、CPA 逐项显示状态与检查时间 | `GET /api/platform/status`；服务端并发探测并设置短时缓存 |
| 待处理事项 | 告诉管理员下一步做什么 | 严重/待处理模拟告警、临期模拟 Key，并可进入对应页 | `GET /api/tasks/summary` 从 SQLite 聚合告警和掩码 Key；不包含完整凭据，不代表真实事件 |
| 首次配置清单 | 引导完成最小链路 | 渠道、模型别名、测试 Key、客户端验证 | 平台数据库保存步骤状态；已验证和人工确认分开 |
| 外部入口 | 打开现有后台和文档 | New API、CPA、项目文档 | 地址由服务端配置返回；仅保存 URL，不包含登录参数 |

### P02 运营总览

| 功能点 | 作用 | 页面表现 | 实现方式 |
| --- | --- | --- | --- |
| 五项核心指标 | 快速判断今天的运行情况 | 请求、Token、成本点数、成功率、P95 | `GET /api/overview?period=7d|30d` 聚合 SQLite 模拟调用元数据；不等同于真实账单 |
| 趋势图 | 观察流量与成本变化 | 7/30 天请求和成本点数双序列 | BFF 按 Asia/Shanghai 日期聚合 SQLite 记录；ECharts 仅负责展示 |
| 分布分析 | 找到主要消耗来源 | 人员、主要用途和业务模型别名 | BFF 在服务端聚合，不把原始模型、成本金额或错误正文发送到浏览器 |
| 目标状态表 | 找到已配置个人目标的对象 | 使用比例或“未配置” | 仅对已保存的个人月度软目标计算比例；未配置时不伪造比例，一期不得自动阻断 |
| 异常队列 | 提示近期处置事项 | 最近未关闭事件、安全对象与触发值 | 从 SQLite 告警事件读取摘要；不返回上游完整错误正文 |
| 渠道摘要 | 查看模拟调用分布 | 业务别名、成功率、P95、请求量 | 按 SQLite 调用元数据聚合；不等同于实时健康检查，实验标记不提供认证详情 |
| 刷新和来源 | 判断数据是否最新可信 | 更新时间、刷新、`SQLite · 模拟数据` | 刷新取消前一请求；接口显式返回 `database/simulated` 来源与生成时间 |

### P03 人员与部门

| 功能点 | 作用 | 页面表现 | 实现方式 |
| --- | --- | --- | --- |
| 人员检索筛选 | 快速定位员工 | 姓名、岗位、负责人和用途在短暂输入停顿后实时筛选；部门、状态、目标状态即时筛选 | `GET /api/people`，前端 240ms 防抖，服务端分页与权限范围过滤 |
| 人员表格 | 比较人员状态和用量 | 姓名、部门、岗位、负责人、Key 数、软目标、最近调用 | New API 用户数据与平台组织扩展表合并 |
| 部门视图 | 观察部门层级和预算 | 左侧部门树或部门筛选 | 平台数据库维护组织关系；部门负责人只能看本部门 |
| 人员状态 | 处理本地演示账号停用 | 在职、停用、离职待回收 | `POST /api/people/:id/disable`；管理员 + CSRF + 原因确认 + 幂等编号，在同一 SQLite 事务中停用人员并回收其仍有效 Key，写入不含原因原文的审计摘要；不调用 New API |
| 批量导入 | 降低试点人员初始化成本 | CSV 模板、预检、错误行和确认 | 后置写功能；服务端事务导入，不接受包含完整 Key 的文件 |

### P04 人员详情

| 功能点 | 作用 | 页面表现 | 实现方式 |
| --- | --- | --- | --- |
| 基础档案 | 明确人员归属和状态 | 姓名、部门、岗位、负责人、在职状态 | `GET /api/people/:id`，根据角色校验数据范围 |
| 个人指标 | 判断使用和目标情况 | 点数、剩余比例、请求、Token、成功率、最近调用 | 聚合指定人员用量；口径与总览一致 |

| 允许模型 | 检查岗位权限 | 业务模型别名与用途 | 合并人员、用途和路由策略 |
| 管理操作 | 停用本地演示人员或调整软目标 | 停用确认抽屉说明关联 Key 回收和本地登录影响 | 人员停用已支持幂等、二次确认、CSRF 与审计；软目标调整仍关闭 |

### P05 Key 管理

| 功能点 | 作用 | 页面表现 | 实现方式 |
| --- | --- | --- | --- |
| Key 列表与筛选 | 管理全部访问凭据 | 人员、用途、模型、状态、到期、用量、最后使用 | `GET /api/keys`，服务端分页并只返回掩码 |
| 详情抽屉 | 查看权限与来源限制 | 模型范围、有效期、设备备注、IP 限制 | `GET /api/keys/:id`；敏感字段固定脱敏 |
| 创建 Key | 为人员或系统签发独立凭据 | 人员、用途、模型、到期、备注表单 | `POST /api/keys`；明文只在成功后返回一次，不写日志 |
| 停用 Key | 处理本地演示凭据异常 | 明确 SQLite 影响范围、原因确认和不可恢复提示 | `POST /api/keys/:id/disable`；管理员 + CSRF + 幂等编号，状态与不含完整 Key/原因原文的审计摘要同事务写入；不调用 New API |
| 轮换 Key | 定期轮换本地演示凭据 | 明确旧 Key 立即停用、新 Key 继承范围、有效期与一次性展示提示 | `POST /api/keys/:id/rotate`；管理员 + CSRF + 原因确认 + 幂等编号；新旧状态和不含完整 Key/原因原文的审计摘要同事务写入，重试不再次返回完整新 Key；不调用 New API |
| 连接说明 | 降低客户端配置错误 | 复制 Base URL、模型别名和非敏感步骤 | 只生成说明，绝不把管理密钥或其他人员 Key 放入页面 |

### P06 额度与限流

| 功能点 | 作用 | 页面表现 | 实现方式 |
| --- | --- | --- | --- |
| 五层额度树 | 理解公司到 Key 的预算约束 | 公司、部门、人员、用途、Key 层级 | 平台策略表维护继承关系；BFF 返回命中层级 |
| 周期与用量 | 判断剩余目标 | 小时、日、周、月上限、已用、预留、重置时间 | 聚合用量账本；统一时区和失败/重试结算规则 |
| RPM/TPM/并发 | 防止流量突增和资源抢占 | 当前限制、实时值和命中次数 | 网关执行；页面只管理经过验证的策略 |
| 软/硬模式 | 区分提示与阻断 | 一期软目标；硬模式显示上线条件 | 硬模式必须依赖额度预留、实际结算与并发一致性测试 |
| 月度软目标调整 | 在本地演示中调整提示阈值 | 当前用量、预留、目标值与调整后预计使用率；明确不会阻断 | `PATCH /api/limits/:id`；仅管理员、CSRF、原因确认和幂等编号，策略与不含原因原文的审计摘要同事务写入 SQLite；固定为软模式，不调用 New API |
| 临时额度申请 | 支持短期项目或审批 | 生效时间、到期时间和原因 | 二期功能；自动到期、审批与审计完成后开放 |

### P07 用途与路由

| 功能点 | 作用 | 页面表现 | 实现方式 |
| --- | --- | --- | --- |
| 用途目录 | 用业务语言代替供应商模型名 | 文案、客服、翻译、分析、自动化、实验 | 平台数据库维护用途、数据等级和允许岗位 |
| 模型别名 | 保持客户端配置稳定 | `ecommerce-copy` 等业务别名 | BFF 映射平台用途与 New API 模型配置 |
| 主备路由 | 明确请求实际走向 | 默认渠道、实际模型、备用模型 | `GET /api/routes`；当前只读主备目标固定，修改前必须验证渠道和模型存在 |
| 正式/实验隔离 | 防止正式故障误用 Pro OAuth | 正式与实验标签、禁止跨组提示 | 服务端规则拒绝正式别名回退到 CPA 分组 |
| 本地降级策略调整 | 验证演示环境中的故障处理方式 | 超时、429、5xx 的有限重试或同组备用切换 | `PATCH /api/routes/:id` 仅写入 SQLite 覆盖项；管理员、CSRF、原因确认和幂等编号必填；无同组备用渠道时服务端拒绝切换；不允许客户端指定渠道、跨组回退或修改真实路由 |

### P08 模型与渠道

| 功能点 | 作用 | 页面表现 | 实现方式 |
| --- | --- | --- | --- |
| 模型目录 | 查看可用能力与价格口径 | 能力、上下文、价格、区域、状态 | `GET /api/models` 适配 New API 模型和平台扩展字段 |
| 渠道矩阵 | 比较正式和实验渠道 | 渠道、实际模型、类型、健康、延迟、成功率 | `GET /api/channels`，模拟快照可由本地 SQLite 覆盖 |
| 业务别名关联 | 确认模型服务哪些用途 | 别名、用途、默认/备用标记 | 与路由接口使用相同领域对象，避免重复配置 |
| 渠道详情 | 定位失败原因 | 最近错误、限流、余额状态、最近检查 | 仅返回分类和摘要，不返回上游完整响应或凭据 |
| 本地模拟复检 | 验证渠道健康展示和审计闭环 | “模拟复检”确认抽屉与更新时间 | `POST /api/channels/:id/check` 仅刷新 SQLite 合成快照；管理员、CSRF、原因确认和幂等编号必填；不允许输入 URL，不访问上游或 New API |

本轮已交付（2026-09-17）：

- 默认保持“模拟数据”，含 4 个模型、5 个渠道；管理员可主动切换“New API 数据”。两个接口使用 `source=demo|new_api` 参数，响应分别标记 `demo` / `new_api`，不混合或自动回退。
- 只读映射模型元数据及已配置渠道中的模型名称、稳定 ID、停用状态与精确关联。上游分页完整读取后再筛选，每类最多 2,000 条；30 秒缓存只保存白名单转换后的配置摘要，并合并并发读取。
- 价格、上下文、能力、环境、余额、成功率、P95、凭据配置等缺失字段显示“未提供 / 未归类 / 待验证”。渠道已启用不等于调用健康，接口探测耗时不作为 P95；全局支持的模型清单不作为已配置目录。
- 已覆盖真实空列表、无权限、管理认证失败、不可达、格式异常、读取上限和重试；切换来源时清空旧内容、取消旧请求，防止较晚的响应覆盖当前来源。详情支持键盘焦点与 Escape 关闭。
