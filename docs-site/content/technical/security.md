# 安全、权限与审计

## 1. 安全目标

平台必须保护四类高价值对象：员工身份、员工 Key、上游中转站凭据，以及员工上传或生成的媒体。任何一类泄露都可能产生越权调用、费用损失或隐私风险。

## 2. 角色与授权

| 操作 | 超级管理员 | 员工 | 系统服务 |
| --- | --- | --- | --- |
| 管理中转站、路由与预算 | 允许 | 拒绝 | 受限执行 |
| 查看全局监控和成本 | 允许 | 拒绝 | 受限写入 |
| 注册、登录和管理自己会话 | 不适用 | 允许 | 不适用 |
| 使用自己的 Key | 可用于受控测试 | 允许 | 仅服务身份 |
| 查看其他员工 Key、密码或媒体 | Key 和密码始终拒绝；媒体仅按审计授权 | 拒绝 | 拒绝 |
| 撤销设备或 Key | 允许 | 仅自己的 | 按策略 |

所有授权都在服务端执行。隐藏按钮不是权限控制；员工若构造管理员路径必须得到拒绝。

## 3. 密码、会话和 Key

- 密码使用现代抗暴力破解的不可逆摘要算法，并配置唯一盐和合理成本。
- 登录启用速率限制、可疑登录检测和安全重置流程。
- 会话 Cookie 设置 HttpOnly、Secure 和适当 SameSite；写操作使用 CSRF 防护。
- 服务端保存 Key 的不可逆校验摘要、掩码和 AES-GCM 加密副本。完整 Key 只会通过 Key 所有者的已认证门户响应显示或复制，管理员接口、人员列表、URL、浏览器持久化存储和普通日志绝不返回它。
- Key 校验使用常量时间比较，撤销状态在缓存中快速生效。
- 设备令牌与员工 Key 分开，每台设备独立可撤销。
- 超级管理员应启用多因素认证、短会话和受限来源访问。

## 4. 上游凭据和密钥管理

中转站 API 凭据只由服务端密钥管理系统读取。数据库仅保存引用、掩码、轮换时间和状态，不能保存可直接使用的明文。

要求：

- 凭据不进入浏览器、下载包、客户端配置、错误页或普通日志。
- 凭据轮换必须支持双版本短暂重叠和健康验证。
- 第三方服务地址默认仅接受公共 HTTPS 地址，并拒绝本机、内网和保留 IP；部署方可用精确主机白名单收紧范围，并应配置出站网络限制以防 DNS 重绑定类 SSRF。
- 适配器只能访问其被批准的上游域名与端口。
- 不接受员工自定义上游地址、回调地址或任意代理配置。

## 5. 数据与媒体保护

| 数据 | 默认处理 |
| --- | --- |
| 员工资料 | 最小化保存、加密传输、严格 RBAC |
| 请求元数据 | 记录 request_id、模型、耗时、用量和结果状态 |
| 提示词与生成文本 | 作为员工会话记录加密持久化，账户有效期间不可因日志淘汰丢失；访问、导出和明确删除均需审计 |
| 上传和生成媒体 | 对象存储私有桶、按员工隔离、短时签名访问 |
| 视频和图片资产 | 设定保留期、到期删除、可选恶意文件扫描 |
| 日志 | 去除 Authorization、Cookie、密码、Key、设备令牌和上游响应敏感字段 |

会话保存不代表任何管理员可随意浏览内容。任何查看或导出都应最小化、可审计、可设置有效期，且不得自动包含完整 Key 或凭据。

## 6. 网关防护

- 对 IP、员工、Key、模型、模态和设备分别实施速率与并发限制。
- 文本、图片、视频队列隔离，避免高成本作业压垮登录或文本服务。
- 在预算预占后才提交图片和视频任务，防止并发超支。
- 请求体、文件大小、媒体类型、提示词长度和模型参数均按目录校验。
- 所有副作用请求使用 Idempotency-Key，防止网络重放造成重复消费。
- 给每个请求、作业和管理操作分配 request_id，方便排障但不泄露用户数据。

## 7. 审计与告警

必须审计：

- 超级管理员登录、失败登录、MFA、安全设置和会话撤销。
- 中转站、模型、路由、预算、目录发布的创建、变更、停用和删除。
- 员工停用、Key 轮换、设备授权和设备撤销。
- 高成本作业创建、取消、失败、预算预占和结算。
- 导出、敏感内容查看和策略例外。

告警覆盖异常错误率、认证失败激增、Key 共享嫌疑、预算异常、单站熔断、队列积压、媒体资产下载异常和连接器版本过旧。

## 8. 事件响应

发生疑似 Key 或中转站凭据泄露时：

1. 立即撤销受影响 Key 或中转站凭据。
2. 冻结相关路由和设备令牌，保留最小必要审计证据。
3. 分析 request_id、用量变化、来源和时间范围。
4. 轮换凭据、重新验证健康、恢复最小可用路由。
5. 通知受影响员工并要求重新连接客户端。
6. 记录根因、影响、处置和预防措施。

不得通过复制日志、截图或把敏感内容发到聊天中进行排障。
