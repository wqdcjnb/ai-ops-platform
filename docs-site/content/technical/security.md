# 安全方案

::: info 当前安全边界
AI OPS 只有超级管理员入口。CPA 和 New API 随 Docker Compose 启动，管理凭据只在 AI OPS 服务端使用；管理员不需要进入它们的管理网站。当前员工客户端尚未建设，未来客户端只使用 New API 员工 Token/API Key。
:::

## 1. 凭据分层

| 凭据 | 保存方 | 用途 | 浏览器/员工是否可见 |
| --- | --- | --- | --- |
| Codex OAuth 认证文件 | CPA 持久化目录 | CPA 访问 Codex | 否 |
| CPA 管理 Key | 服务端运行配置/CPA | 读取账号、模型、额度和 OAuth 状态 | 否 |
| CPA 客户端 API Key | CPA 配置 + AI OPS 服务端 | New API 创建/更新 CPA 渠道 | 否 |
| New API 管理令牌 | AI OPS 服务端运行配置 | 管理人员、渠道、Token 和日志 | 否 |
| New API 员工 Token/API Key | New API | 未来员工调用入口 | 只在创建成功后向超级管理员一次性显示 |

AI OPS 只保存 New API `token_id`、掩码、人员映射、模型和同步状态。不得保存 CPA OAuth 原文、刷新令牌、CPA 客户端 Key 明文、New API 管理令牌或员工 Key 明文。

## 2. 网络与入口

- 浏览器只访问 AI OPS 前端和 BFF；前端不得直连 New API/CPA 管理接口。
- 不在 AI OPS 中嵌入 New API/CPA 管理页面，不提供后台链接作为日常操作入口。
- Compose 内使用服务名访问 `new-api` 和 `cpa`；宿主机调试端口即使绑定到 `127.0.0.1`，也不代表对外开放或属于业务流程。
- 管理接口不应映射到公网；生产部署应通过内网、VPN 或零信任网络保护 AI OPS 管理入口。
- 只允许固定的 New API/CPA 服务地址，禁止管理员在浏览器提交任意上游 URL，避免 SSRF。
- 依赖状态由 AI OPS 聚合展示，至少包括 `starting`、`ready`、`degraded`、`auth_required` 和 `sync_failed`。

## 3. 服务端适配器

所有 New API/CPA 读写都经由 AI OPS Server：

- 统一校验响应结构和版本，敏感字段只保留掩码或摘要；
- 写操作携带幂等键，记录上游响应摘要、版本、同步时间和错误原因；
- Compose 启动、重启或配置漂移后自动探测并幂等同步 CPA 渠道；
- 上游不可达、认证失败或字段不兼容时禁止写入本地成功状态；
- 超时、部分成功和重复提交进入可恢复状态，不由浏览器自行重试造成重复 Token/渠道；
- 认证、模型、额度和渠道结果都在 AI OPS 页面展示，不能要求管理员切换到上游网站。

## 4. New API Token 安全规则

- 一个 Token 只能绑定一个人员和一个模型；一个人员或模型可以有多个 Token。
- 人员停用必须调用 New API 停用该人员的全部 Token，并显示逐项结果。
- 创建时启用单模型限制、无限额度和永不过期；具体字段按当前 New API 版本适配，不能由 AI OPS 自己扣减额度。
- 完整员工 Key 只在创建/重新生成成功后显示一次；列表、日志、错误、导出和审计只显示掩码或外部 ID。
- 停用、删除、重新生成和渠道变更必须以 New API 实际返回为准；本地映射不能单方面覆盖事实源。
- CPA 客户端 API Key 永远不能登记为员工 Key、写入分发记录或返回给外部客户端。

## 5. OAuth 与额度

- Codex OAuth 流程由 AI OPS 发起，必要时只短暂跳转官方授权页，完成后回到 AI OPS；不要求打开 CPA 管理面板。
- OAuth 文件只由 CPA 读取和刷新，AI OPS 只能读取账号标识、状态和必要摘要。
- CPA 账号额度是上游账号池状态，不等于 New API Token 的无限额度，也不在 AI OPS 中虚构人员额度。
- 额度优先通过当前 CPA 管理 `api-call` 适配查询；接口无稳定字段时显示“额度暂不可读”，不得从 OAuth 文件推算。

## 6. 真实正文审计

New API 普通日志可能只有 Token、模型、时间、用量和状态。为了按 Key 查看真实 Prompt 和回复正文，必须在 New API 真实请求处理边界采集：

- 鉴权成功后取得 `token_id`，关联 AI OPS 内部 `key_id` 和 `request_id`；
- 捕获真实 Prompt、上下文、工具调用和回复正文，拼接流式响应；
- 保存失败、中断和部分响应的真实状态，不用合成内容补齐；
- 正文与元数据分离并加密，普通日志只保存摘要、长度和哈希；
- 自动过滤 Authorization Header、Cookie、OAuth、刷新令牌、完整 Key 和其他凭据；
- 正文最多保留 30 天，本版默认 30 天，到期自动删除并留下不含正文的删除证明；
- 只有超级管理员可以查看、复制和导出，每次操作记录 Key、`request_id`、时间、原因和范围。

以前没有采集正文的请求必须显示“无正文记录”，不能根据 Token 数量或示例文本恢复。

## 7. 管理会话与操作审计

- AI OPS 只保留超级管理员；不提供员工登录、普通管理员、多级审批或员工自助端。
- 会话 Cookie 使用 HttpOnly、Secure（生产）和 SameSite 保护；写操作启用 CSRF 防护和幂等键。
- 人员导入、Key 创建/查看/分发/停用/删除、OAuth 操作、渠道同步、正文查看/复制/导出和失败重试都写入管理审计。
- 管理审计不得写入密码、Cookie、Token、OAuth、完整 Key、Authorization Header 或正文原文。
- 审计记录保留对象 ID、时间、操作类型、结果、错误摘要和必要的字段差异。

## 8. Docker 与数据保护

- `deploy/cpa/auths/`、CPA 配置、New API 数据库、平台数据卷和 `.env` 必须在 Git 忽略范围。
- 生产镜像应固定版本，不使用未经评估的浮动 `latest`；升级前保留可回滚版本。
- 数据库、备份和正文审计存储应加密，正文加密密钥不得与正文放在同一存储中。
- 不把运行日志、认证文件、数据库、备份或审计导出文件提交到仓库。
- 停止/重启服务后验证健康、映射、渠道和审计状态；失败恢复不能生成重复 Key。

## 9. 上线阻断条件

出现以下任一情况不得进入正式使用：

- 浏览器可以取得 New API/CPA 管理凭据，或通过前端直连/iframe 操作上游后台；
- CPA 客户端 API Key 被当作员工 Key 分发；
- 人员停用后仍有 New API Token 可调用；
- Key 的模型限制、额度或有效期只存在 AI OPS 本地，未在 New API 生效；
- 日志、错误、导出或正文存储出现完整 Key、OAuth、Authorization Header 或未脱敏凭据；
- New API/CPA 不可达时页面使用演示数据冒充真实成功；
- 真实 Prompt/回复无法按 Key、`token_id`、`request_id` 关联，或正文查看没有访问审计；
- 正文超过 30 天仍可访问且没有删除证明。
