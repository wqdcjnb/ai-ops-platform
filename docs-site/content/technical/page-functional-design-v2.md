# 页面功能设计 V2（内部测试版）

::: info 文档定位
本文是第一版原型进入内部测试后的第二版页面设计与完成表。V2 的目标是把现有本地 SQLite 模拟能力整理成可重复、可审计、可回归的内部测试版本；它不是生产上线设计，也不把模拟数据描述成真实业务数据。
:::

## 1. V2 范围与使用边界

### 1.1 本版目标

- 让运营、管理员和员工可以用演示账号走通主要业务流程。
- 让每个写操作都有权限、CSRF、幂等、确认和本地审计记录。
- 让所有页面都明确展示 `LIVE`、`PARTIAL`、`DEMO` 或 `UNVERIFIED` 数据来源。
- 让搜索、筛选、详情、导出和回溯形成一致的内部验收路径。
- 建立可重复的 SQLite 种子、测试数据库和浏览器验收入口。

### 1.2 明确不在 V2 范围内

- 不接入真实员工目录、真实 Key、真实账单或真实调用正文。
- 不启用硬额度阻断、真实网关额度同步、真实告警通知和真实 CPA 授权。
- 不把合成对话审计当作真实对话存储，也不开放复制、导出和删除。
- 不以内部测试通过作为生产安全、性能、备份恢复或合规验收结论。

### 1.3 内部测试角色

| 角色 | 测试重点 | 数据范围 |
| --- | --- | --- |
| 超级管理员 | 所有页面、对话审计原因门禁、版本回滚 | 全局模拟数据 |
| 管理员 | 人员、Key、额度、路由、告警写操作 | 全局模拟数据 |
| 部门负责人 | 本部门人员、Key、额度和告警 | 服务端按部门过滤 |
| 财务 | 成本和额度只读 | 费用摘要和只读模拟数据 |
| 员工 | 员工自助和临时额度申请 | 仅当前会话员工 |

## 3. 页面功能设计

每行同时说明“功能点—作用—实现方式”。页面中的写操作必须由 BFF 决定是否允许，前端按钮禁用只能作为体验提示，不能作为安全边界。

| 页面 | 功能点 | 作用 | 实现方式 |
| --- | --- | --- | --- |
| P01 统一入口 | 服务矩阵、入口卡、待办、首次配置 | 让测试人员快速判断环境并进入下一项流程 | Vue 首页调用 `/api/platform/status`、`/api/tasks/summary`；服务状态分开显示 BFF、New API、CPA；待办读取 SQLite 模拟摘要 |
| P02 运营总览 | 指标、趋势、排行、异常入口 | 验证聚合口径、角色范围和异常跳转 | `/api/overview` 从 SQLite 调用、额度和告警元数据聚合；页面标注 `DEMO`，部门负责人由 BFF 收窄到本部门 |
| P03 人员与部门 | 实时搜索、组合筛选、添加人员、CSV 预检/批量导入、停用 | 验证人员主数据和批量写入流程 | `/api/people` 查询；`POST /api/people` 与导入事务写入 SQLite；使用用户名幂等键、CSRF、原因长度和操作审计；搜索输入停顿后即时请求，不要求点击查询 |
| P04 人员详情 | 资料、用量、Key 摘要、模型白名单、月度软目标、停用 | 验证个人级权限、策略同步和影响范围 | `/api/people/:id` 返回脱敏资料；白名单更新人员策略并同步仍有效 Key；软目标和停用与审计同事务；跨部门详情由 BFF 返回未找到 |
| P05 Key 管理 | 创建、一次性明文展示、筛选、详情、停用、轮换 | 验证凭据最小暴露和生命周期流程 | `/api/keys` 只返回掩码；创建/轮换仅首次返回完整值；停用/轮换要求 CSRF、确认和幂等号；SQLite 事务记录字段摘要，不写完整 Key |
| P06 额度与限流 | 五层额度树、软目标调整、临时申请审批、预留/结算/取消 | 验证额度策略和失败回滚路径，但不阻断请求 | `/api/limits` 读取层级与模拟计量；`quota-reservations` 接口保存本地预留状态；申请、审批、结算、取消均幂等并写审计；硬额度开关固定关闭 |
| P07 用途与路由 | 用途筛选、主备渠道、超时/429/5xx/重试策略、策略保存 | 验证路由配置的可读性和变更回溯 | `/api/routes` 读取 SQLite 策略；管理员 PATCH 仅修改本地覆盖项；服务端禁止客户端选渠道和正式/实验跨组回退 |
| P08 模型与渠道 | 来源切换、能力/价格/健康摘要、详情抽屉、模拟复检 | 验证空目录、失败重试和数据来源提示 | 默认读取模拟目录；管理员可请求 New API 只读目录；配置缓存 30 秒；本地复检只写健康快照和审计，不发起真实探测 |
| P09 上游账号 | 官方/CPA 状态、窗口、认证异常、模拟验证、认证历史 | 验证上游健康展示和凭据不泄露 | `/api/upstreams` 返回状态摘要与布尔配置状态；模拟验证只对已配置演示账号开放，历史仅保留操作者、时间、请求 ID 和脱敏摘要 |
| P10 用量与日志 | 多维筛选、同条件汇总、分页、详情、来源关联 | 验证排障和告警/审计跳转 | `/api/usage` 只读 SQLite 模拟调用元数据；请求 ID 关联使用严格白名单；详情不返回正文；成本字段分为官方实际、平台估算、CPA 估算 |
| P11 告警中心 | 事件/规则、严重度筛选、确认、关闭、规则编辑 | 验证处置责任、幂等重放和审计回溯 | `/api/alerts` 读取本地事件；确认/关闭/规则 PATCH 要求 CSRF、说明确认和幂等号；状态变更与审计同事务；通知渠道保持未配置 |
| P12 审计日志 | 组合筛选、详情、CSV 导出、SHA-256 链校验 | 验证操作可追溯和本地证据导出 | `/api/audit-events` 只返回脱敏摘要；导出最多 500 条并再次写审计；读取时校验事件数、链头和顺序，发现篡改拒绝继续追加 |
| P13 对话审计 | 采集范围、脱敏轮次、查看原因、访问历史、到期状态 | 验证高风险内容的最小访问门槛 | 仅超级管理员可访问；SQLite 只保存合成元数据和预先脱敏轮次；访问原因只保存长度；原始正文、复制、导出和删除固定不可用 |
| P14 系统设置 | 业务口径草稿、差异预览、发布、回滚、版本历史 | 验证配置变更的版本化和可回退性 | `/api/settings/business-rules/*` 仅修改 SQLite；草稿、发布和回滚写入版本历史及审计；服务连接、留存、备份等分区保持只读或未配置 |
| P15 员工自助 | 本人资料、掩码 Key、本人用量、可用模型、连接说明、临时额度申请 | 验证本人范围和员工申请入口 | `/api/me/*` 根据会话员工 ID 查询；不返回其他人员、完整 Key、供应商或真实渠道；申请交由管理员/负责人在 `/limits` 审批 |

## 4. 公共交互与验收规则

### 4.1 搜索与筛选

- 所有列表搜索统一为实时搜索：输入停止约 240ms 后请求，清空立即恢复全量列表。
- 搜索、筛选、分页和详情跳转必须保留 URL 查询参数，返回后可清除关联来源。
- 服务端必须再次执行角色和部门范围过滤，不能依赖前端隐藏选项。
- 空结果、上游失败、未配置和无权限使用不同状态文案，不用颜色单独表达。

### 4.2 写操作

所有本地写操作统一具备：服务端 RBAC、CSRF、幂等操作编号、二次确认、事务提交、敏感字段脱敏审计和重放结果。写操作页面必须明确提示“仅修改本地 SQLite，不会修改真实 New API/CPA”。

### 4.3 测试数据与重置

- 每个浏览器流程使用隔离 SQLite 数据库，测试结束后可销毁并重新运行种子。
- 演示种子必须固定人员、Key、额度、告警、审计和合成对话记录数量，便于截图和回归。
- 测试人员不得把生产密码、真实 API Key 或真实对话复制到本地数据库。

## 6. 内部测试执行顺序

1. 使用演示管理员登录，完成 P03 添加人员和 CSV 导入。
2. 进入人员详情，修改模型白名单和软目标，回到 P12 核对审计。
3. 创建、轮换并停用演示 Key，确认完整值只出现一次。
4. 用员工账号提交临时额度，再用管理员或部门负责人审批并核对到期状态。
5. 在 P06 演练额度预留的结算、取消和幂等重放。
6. 在 P11 编辑一条本地规则、确认或关闭告警，再跳转 P12 回溯。
7. 在 P14 发布并回滚一版业务口径，核对版本历史。
8. 用超级管理员在 P13 仅查看合成脱敏内容，确认原因门禁和访问记录。

内部测试记录应包含：测试角色、数据库种子版本、页面路由、操作编号、结果、截图或请求 ID。发现问题时不要上传真实凭据和真实对话内容。

## 7. V2 结束定义

V2 内部测试版在以下条件满足后关闭本轮：

- P01–P15 的内部状态均有人工验收记录；P13 仅验收合成数据。
- P03 的添加人员、批量导入和停用流程在 Playwright 中稳定通过。
- 创建 Key、白名单、额度调整、告警处置、设置回滚和审计回溯均可重放且不泄露敏感值。
- 关键失败态、无权限、空数据和移动窄屏页面完成一次回归。
- 仍保留“本地 SQLite、模拟数据、不可用于生产”的显著提示。

达到以上条件只表示“内部测试版完成”，不改变真实数据接入、生产安全和正式上线的验收门槛。
