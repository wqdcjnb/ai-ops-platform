# 页面规划 V2

::: info 规划依据
本文依据《AI 运营平台-项目文档-更新版-合并版》重新整理页面信息架构。新版补充了对话审计、超级管理员、员工自助、用途路由和多层额度要求；本规划将需求清单与最终页面信息架构合并为一套可开发结构。
:::

## 1. 规划结论

平台不再使用“一个总览页承载所有功能”的结构，而是拆成两个入口：

```text
登录后角色分流
├─ 管理控制台
│  ├─ 工作台
│  ├─ 人员与访问
│  ├─ 模型治理
│  ├─ 运营监控
│  ├─ 安全审计
│  └─ 系统管理
└─ 员工自助
   ├─ 我的 Key
   ├─ 我的用量
   ├─ 可用模型
   └─ 接入说明
```

管理员控制台用于全局治理，员工自助端只显示当前用户数据。两者共享登录与视觉体系，但不共用侧栏，避免普通员工看到无权限菜单。

## 2. 管理端信息架构

### 2.1 侧栏分组

| 分组 | 页面 | 路由 | 一期处理 |
| --- | --- | --- | --- |
| 工作台 | 统一入口 | `/` | 服务入口、待处理事项和环境状态 |
| 工作台 | 运营总览 | `/overview` | 核心指标、趋势、异常和健康状态 |
| 人员与访问 | 人员与部门 | `/people` | 人员列表；详情进入 `/people/:id` |
| 人员与访问 | Key 管理 | `/keys` | 独立表格，不再与人员页混排 |
| 人员与访问 | 额度与限流 | `/limits` | 只读策略与软目标；写操作后置 |
| 模型治理 | 用途与路由 | `/routes` | 业务用途、模型别名、主备路由 |
| 模型治理 | 模型与渠道 | `/models` | 能力、价格、正式/实验标签和健康状态 |
| 模型治理 | 上游账号 | `/upstreams` | 官方渠道与 CPA 状态，不展示凭据 |
| 运营监控 | 用量与日志 | `/usage` | 多维筛选、请求 ID 和脱敏详情 |
| 运营监控 | 告警中心 | `/alerts` | 规则、事件、确认和处理记录 |
| 安全审计 | 审计日志 | `/audit` | Key、权限、路由、导出等管理操作 |
| 安全审计 | 对话审计 | `/conversation-audit` | 超级管理员专属；正文与用量日志隔离 |
| 系统管理 | 系统设置 | `/settings` | 角色、数据留存、时区和服务连接状态 |

项目文档、新旧后台属于外部入口，放在侧栏底部，不与业务页面混在同一导航层级。

### 2.2 角色可见范围

| 页面 | 超级管理员 | 管理员 | 部门负责人 | 财务 | 员工 |
| --- | --- | --- | --- | --- | --- |
| 统一入口 / 总览 | 全局 | 全局运营范围 | 本部门 | 成本摘要 | — |
| 人员与部门 | 全部 | 试点人员 | 本部门 | — | — |
| Key 管理 | 全部 | 创建与停用 | 本部门只读 | — | — |
| 额度与限流 | 全部 | 软目标 | 本部门申请与调整 | 只读 | — |
| 模型、路由、上游 | 全部 | 只读或受控操作 | 只读 | — | — |
| 用量与日志 | 全部 | 元数据 | 本部门元数据 | 费用数据 | — |
| 告警 / 审计日志 | 全部 | 运营事件 | 本部门事件 | 成本事件 | — |
| 对话审计正文 | 可查看，必须填写原因 | 只看采集状态 | — | — | — |
| 员工自助 | 可模拟查看 | — | — | — | 仅本人 |

权限必须由 BFF 服务端过滤，前端隐藏菜单只用于体验，不能作为授权依据。

## 3. 全局页面框架

桌面端延续 Tabler 高密度工具风：248px 侧栏、56px 顶栏、弹性内容区。表格页使用全宽，总览页最大宽度 1600px。

### 顶栏

- 全局搜索：人员、Key 掩码、请求 ID。
- 环境标识：开发、测试或生产。
- 服务状态：分别展示 BFF、New API、CPA，不再使用“4/5 可用”一类无来源汇总。
- 告警入口、当前角色和用户菜单。

### 通用页面头

- 面包屑、页面标题、用途说明。
- 数据更新时间和刷新按钮。
- 主操作按钮只在权限、连接和功能均可用时启用；否则显示禁用原因。
- 列表页筛选固定在表格上方，轻量详情使用右侧抽屉，复杂配置进入独立页面。

### 状态规则

- 绿色：可用或低于 80%。
- 黄色：达到 80%、即将过期或等待处理。
- 红色：达到 100%、认证失败或服务异常；一期软目标仍不阻断请求。
- 灰色：未配置、无数据或尚未验证。
- 紫色：CPA / Pro OAuth 隔离实验。

所有状态必须同时包含文字和图标，不能只依赖颜色。

## 4. 核心页面设计

### 4.1 统一入口

它是导航首页，不是第二个总览：

- 四张入口卡：运营总览、人员与 Key、上游账号、待处理事项。
- 服务矩阵：BFF、New API、CPA、文档中心。
- 快捷入口：New API 后台、CPA 后台、项目文档；只保存地址。
- 首次使用清单：渠道、模型别名、测试 Key、客户端验证。

### 4.2 运营总览

当前页面保留并收敛为三层：

1. 指标：请求、Token、成本点数、成功率、P95。
2. 判断：7/30 天趋势、人员/部门/模型/渠道分布。
3. 处置：软目标状态、异常队列、渠道健康矩阵。

应移除无数据来源的服务汇总；业务指标为演示数据时必须持续显示来源提示。创建 Key 不是本页主任务，按钮仅在写接口上线后开放。

### 4.3 人员与部门

默认是表格：姓名、部门、岗位、状态、负责人、软目标、Key 数、最近调用。点击人员进入详情页，详情包含个人指标、用量趋势和 Key 列表；每个 Key 在列表中显示用途和唯一绑定模型，人员本身不维护模型白名单。

人员详情不展示完整 Key。停用人员、调整软目标等写操作使用确认抽屉，并展示影响范围。

### 4.4 Key 管理

独立表格包含人员、用途、绑定模型、状态、到期时间、最近使用、当月用量和操作。创建表单要求人员、用途、单个绑定模型、过期时间与备注；同一人员需要多个模型时创建多个 Key。

Key 明文只在创建成功时展示一次；列表、日志、截图和导出只显示掩码。轮换和停用必须二次确认并写入审计。

### 4.5 额度与限流

一期首先展示公司、部门、人员、用途和 Key 五层软目标，以及 RPM、TPM、并发的当前配置。硬额度开关保持禁用，直到并发预留、取消、重试和统计故障测试通过。

### 4.6 用途与路由

以业务用途为主线展示“用途 → 模型别名 → 默认渠道 → 实际模型 → 降级策略”。正式渠道与 CPA 实验渠道不可自动跨组回退。

### 4.7 模型与渠道

采用矩阵和详情抽屉，展示模型能力、价格口径、上下文、业务别名、健康状态和允许用途。官方实际账单与 CPA 估算消耗使用不同字段和标签。

### 4.8 用量与日志

顶部提供日期、人员、部门、用途、Key、模型、渠道、状态和请求 ID 筛选。表格展示元数据和错误摘要；抽屉展示 Token、点数、首 Token、总耗时和渠道，不默认展示请求正文。

### 4.9 上游账号

展示官方渠道健康、余额状态和最近错误；CPA 展示认证有效期、窗口、冷却和刷新时间。所有凭据仅显示“已配置/未配置”，不返回掩码以外的信息。

### 4.10 告警中心

分为事件与规则两个页签。事件支持待处理、已确认、已关闭；规则覆盖 80%/100%、流量突增、错误率、余额和凭据到期。通知渠道未配置时明确显示灰色状态。

### 4.11 审计日志

记录登录、人员、Key、额度、路由、导出和管理配置变更。详情展示变更前后摘要、操作人、时间、来源与结果，不包含完整密钥和对话正文。

### 4.12 对话审计

与用量日志完全分离。列表显示请求 ID、人员、Key、用途、模型、采集策略、脱敏和到期状态。超级管理员填写查看原因后才能打开脱敏轮次；复制、导出、删除再次确认并生成不可由普通管理员删除的访问审计。

## 5. 员工自助端

员工端采用更轻的独立布局，不显示管理侧栏：

- 我的 Key：掩码、状态、有效期和复制接入说明。
- 我的用量：本月软目标、趋势、请求和 Token。
- 可用模型：业务别名、用途和使用建议，不暴露真实渠道。
- 接入说明：Codex Desktop / WorkBuddy 配置和常见错误。
- 临时额度申请放到二期。

## 6. 数据状态

每个页面必须实现六种状态：加载中、正常、空数据、部分上游失败、无权限、首次未配置。上游失败提示应包含服务名、检查时间、重试按钮和请求 ID，不显示上游完整错误正文。

数据来源标签统一为：

- `LIVE`：真实上游数据且完成契约校验。
- `PARTIAL`：部分真实、部分不可用。
- `DEMO`：演示数据。
- `UNVERIFIED`：接口可达但字段或口径尚未验收。

## 7. 开发顺序

### P0：应用骨架与真实状态

1. Vue Router、两套角色布局、权限守卫和错误页。
2. 统一入口页与真实服务状态。
3. 保留并修订运营总览，移除无来源汇总和不可用写按钮。

### P1：三个只读高保真页面

1. 人员与部门 + 人员详情。
2. Key 管理。
3. 用量与日志。

对应 BFF：`GET /api/people`、`GET /api/people/:id`、`GET /api/keys`、`GET /api/usage`。

### P2：治理与异常页面

1. 用途与路由。
2. 模型与渠道。
3. 上游账号。
4. 告警中心与审计日志。

### P3：敏感与写操作

1. 对话审计的采集状态；正文访问必须等独立存储、加密、脱敏和访问审计完成。
2. 告警确认、软目标调整、Key 创建/停用/轮换。
3. 路由与额度写操作。
4. 员工自助端。

硬额度和自动降级不随页面一起提前上线，必须单独通过并发一致性和故障测试。
