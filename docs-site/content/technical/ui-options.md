# UI 候选方案

::: tip 选型结果
已确定使用 **Tabler 高密度工具风**。实现栈为 Vue 3 + TypeScript + Vite + Pinia + Tabler Core + Tabler Icons Vue，图表使用 ECharts。其余方案保留为调研记录，不进入当前实现。
:::

## 1. 筛选标准

候选方案需要适合人员、API Key、模型渠道、用量趋势、告警和审计日志等后台场景，同时满足：

- 桌面端可以承载高密度表格和图表，移动端可以完成查询和简单操作。
- 支持浅色、深色和主题变量，避免所有页面都是同一种蓝白后台。
- 表格、筛选、状态标签、抽屉、表单和图表能力完整。
- 项目来源清楚、允许二次开发，并能与 TypeScript 项目集成。
- UI 与 New API、CPA 解耦，后续更换视觉层不影响网关和数据接口。

## 2. 五个候选方向

| 方案 | 视觉感受 | 技术基础 | 适合本项目的部分 | 需要注意 |
| --- | --- | --- | --- | --- |
| A. Tremor 数据产品风 | 留白较多、数字突出、图表像专业数据产品 | React、TypeScript、Tailwind、Radix | 运营总览、用量趋势、人员排名、模型成本分析 | 不是完整后台模板，人员和 Key 表格需要组合 TanStack Table 等组件 |
| B. Tabler 高密度工具风 | 清晰、克制、类似成熟运维控制台 | Bootstrap 5，可接 React/Vue | 人员、Key、日志和配置表格；组件覆盖最完整 | 默认样式偏传统；图表建议改用 ECharts，避免额外图表库授权问题 |
| C. Arco Design Pro | 边界清楚、紧凑、具有字节系企业产品感 | Vue 3、TypeScript、Pinia、Arco Design | 中文后台、复杂筛选、抽屉表单、权限管理 | 需要重做默认主题和首页布局，否则仍会有模板感 |
| D. Soybean Admin | 柔和、轻量、主题丰富，比 Element Plus 更活泼 | Vue 3、TypeScript、Pinia、UnoCSS、Naive UI | 快速搭建多主题后台，中文生态友好 | 功能和主题选项很多，需要删除无关模块，避免后台显得杂乱 |
| E. Shadcn Dashboard | 黑白极简、现代 SaaS 感、组件边界弱 | React、TypeScript、Vite、Tailwind、shadcn/ui | 员工自助页、设置页、命令搜索和移动端 | 当前使用较广，若直接套模板仍可能产生新的视觉疲劳 |

### A. Tremor 数据产品风

- GitHub：[tremorlabs/tremor](https://github.com/tremorlabs/tremor)
- 预览：[Tremor](https://www.tremor.so/)
- 许可证：Apache-2.0。
- 建议配色：深海军蓝背景、暖白内容面板、青色主数据、橙色告警。
- 页面气质：像“AI 运营数据产品”，弱化传统后台的左侧菜单和方框感。

适合作为本项目的首选视觉方向。首页以用量趋势和异常处理为中心，人员与 Key 进入二级页面。

### B. Tabler 高密度工具风

- GitHub：[tabler/tabler](https://github.com/tabler/tabler)
- 预览：[Tabler Live Demo](https://preview.tabler.io/)
- 许可证：MIT；项目自带的部分第三方图表库需要单独检查授权，本项目可直接使用 ECharts 替换。
- 建议配色：石墨灰、雾蓝、低饱和绿色，状态色只用于异常和阈值。
- 页面气质：像稳定的基础设施控制台，信息密度高，但不压迫。

适合管理员每天长时间查看人员、Key 和调用日志，也最容易做成稳定的内网工具。

### C. Arco Design Pro

- GitHub：[arco-design/arco-design-pro-vue](https://github.com/arco-design/arco-design-pro-vue)
- 预览：[Arco Design Pro Vue](https://vue-pro.arco.design/)
- 许可证：MIT。
- 建议配色：深灰侧栏、白色主区、紫青渐变数据强调，卡片减少边框。
- 页面气质：规整、利落，适合复杂权限和配置流程。

如果团队希望继续使用 Vue，这是最均衡的选择。应保留组件系统，重新设计首页和色彩，不直接照搬演示站。

### D. Soybean Admin

- GitHub：[soybeanjs/soybean-admin](https://github.com/soybeanjs/soybean-admin)
- 预览：[Soybean Admin](https://soybeanjs.cn/)
- 许可证：MIT，使用时保留项目要求的版权信息。
- 建议配色：暖灰背景、鼠尾草绿主色、淡紫实验标签、珊瑚红告警。
- 页面气质：柔和、轻松，主题切换丰富，适合非技术运营人员。

这套更容易摆脱“运维系统”的感觉，但需要控制装饰和动效，避免影响高密度数据阅读。

### E. Shadcn Dashboard

- GitHub：[shadcndashboard/shadcndashboard](https://github.com/shadcndashboard/shadcndashboard)
- 预览：[Shadcn Dashboard Demo](https://shadcndashboard-demo.vercel.app/)
- 许可证：MIT，免费版本要求保留归属链接。
- 建议配色：黑白主体、荧光黄或电光青作为唯一强调色。
- 页面气质：现代、简洁，适合员工自助端和较轻的运营后台。

组件自由度高，但需要自行建立状态色、表格密度和图表规范。直接使用默认灰白主题会比较同质化。

## 3. 三套可落地的视觉提案

### 提案 1：AI 运营指挥台

推荐基础：Tremor + React。

```text
┌────────────────────────────────────────────────────────┐
│ AI OPS   服务状态 ●正常   今日 12,480 请求   管理员头像 │
├─────────┬──────────────────────────────────────────────┤
│ 总览    │ 本月用量曲线                    异常待处理  4 │
│ 人员    │ ─────────────────────────────────────────── │
│ Key     │ [调用量] [成本点数] [成功率] [P95 延迟]     │
│ 模型    │                                              │
│ 日志    │ 人员消耗排行          模型与渠道健康矩阵     │
│ 设置    │                                              │
└─────────┴──────────────────────────────────────────────┘
```

特色是深色状态栏、浅色数据画布和大数字。首页先回答“今天是否正常、谁快用完、哪个渠道有问题”，适合日常运营监控。

### 提案 2：数据工作台

推荐基础：Tabler + React/Vue。

```text
┌────────────────────────────────────────────────────────┐
│ 搜索人员、Key、请求 ID                    + 创建 Key   │
├─────────┬──────────────────────────────────────────────┤
│ 分类导航│ 筛选条件：部门 / 人员 / 模型 / 状态 / 日期   │
│         ├──────────────────────────────────────────────┤
│         │ 姓名  用途  本月点数  状态  最近调用  操作   │
│         │ 王某  文案     62%     正常   10:32     ···   │
│         │ 李某  客服     83%     注意   10:29     ···   │
└─────────┴──────────────────────────────────────────────┘
```

特色是信息密度高、表格优先、颜色克制。适合大量人员、Key 和日志的管理，学习成本最低。

### 提案 3：柔和运营空间

推荐基础：Soybean Admin + Vue。

```text
┌────────────────────────────────────────────────────────┐
│ 早上好，运营管理员                         9 月 15 日  │
│                                                        │
│ [团队用量 64%]  [活跃人员 8]  [健康渠道 5]  [告警 2] │
│                                                        │
│ 本周趋势                     需要关注                  │
│ ╭────────────────────╮      ╭────────────────────╮    │
```

## 4. Tabler 最终视觉规范

### 布局

- 桌面端采用 248px 左侧导航、56px 顶部工具栏和弹性内容区。
- 总览页最大内容宽度 1600px；表格页使用可用全宽，避免窄内容区浪费空间。
- 首屏放置 4–5 个紧凑指标卡，不使用大面积欢迎语和装饰插画。
- 筛选条件固定在表格上方；详情和轻量编辑使用右侧抽屉，复杂配置使用独立页面。
- 手机端导航收进抽屉，只保留查看、筛选和停用等关键操作。

### 颜色

| 用途 | 色值 | 使用位置 |
| --- | --- | --- |
| 页面背景 | `#F6F8FB` | 主内容背景 |
| 导航深色 | `#182433` | 左侧导航和重要标题 |
| 品牌色 | `#146C70` | 主按钮、当前导航和主要曲线 |
| 正常 | `#2FB344` | 健康渠道、80% 以下用量 |
| 注意 | `#F59F00` | 达到 80%、即将过期 |
| 异常 | `#D63939` | 达到 100%、认证或服务错误 |
| 实验 | `#AE3EC9` | CPA 和 Pro OAuth 实验渠道 |

品牌色从 Tabler 常见蓝色改为低饱和墨绿色，减少通用模板感。正式渠道、实验渠道和异常状态不得共用同一种强调色。

### 组件

- 卡片圆角统一为 8px，使用细边框和轻阴影，不使用大面积玻璃效果。
- 表格默认行高 44px，支持紧凑模式、固定表头、列显隐和保存筛选条件。
- 数字使用等宽数字特性；金额、Token、百分比和延迟右对齐。
- 状态同时使用文字、颜色和图标，不能只靠颜色区分。
- 图标统一使用 Tabler Icons 的 2px 线性风格，不混用多套图标。
- 中文正文使用 `Segoe UI`、`Microsoft YaHei` 和系统无衬线字体。
- ECharts 图表减少网格线和装饰，默认显示 7 天，支持切换 30 天。

### 首页风格

最终采用“数据工作台”布局：顶部为全局搜索和创建 Key；中部为指标卡、用量趋势和异常队列；下部为人员消耗排行与渠道健康矩阵。首页首先回答当前是否正常、谁接近月度目标、哪个渠道需要处理。

## 5. 固定规则

无论选择哪套外观，业务结构保持不变：总览、人员、Key、模型渠道、用量日志、上游账号、告警、审计和设置。UI 只改变布局、组件和视觉语言，不改变 New API + CPA 的数据边界。

正式开发前先交付三个 Tabler 高保真页面：运营总览、人员与 Key、用量日志。三个页面确认后再开发完整功能；颜色、字号、间距、表格密度、图表和移动端规则以上述规范为准。
