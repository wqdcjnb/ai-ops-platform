# 实施路线图

## 1. 交付原则

最终方案不是对历史控制面或单模型 Key 的小修补。实施必须把身份、模型目录、网关、媒体作业和客户端连接器作为独立能力逐步交付。每个阶段都有可运行验收，不以页面原型代替真实请求链路。

## 3. 阶段 0：冻结旧方案与迁移准备

目标：确保已下线的控制面、单模型 Key 和旧管理文档不会继续影响新实现。

交付物：

- 删除或隔离旧产品文档，并以本方案为唯一基线。
- 标记旧数据库表、接口、Compose 服务和前端页面的迁移状态。
- 导出可恢复的数据备份，但不在新平台继续依赖已下线的身份或凭据语义。
- 建立新领域模型的迁移计划：用户、Key、中转站、AI OPS、内部路由、会话、作业、资产和计量。
- 制定数据保留、日志和媒体资产迁移原则。

退出条件：团队确认旧代码不是新验收标准；不存在会向员工分发上游或旧系统 Key 的默认路径。

## 4. 阶段 1：身份、员工门户与基础设施

目标：先建立真实员工身份和安全基础，不让网关依赖匿名或演示数据。

交付物：

- 一个受控初始化的超级管理员和员工注册、邮箱验证、邮箱密码登录。
- 密码安全、会话、CSRF、登录限流、账户停用与安全审计。
- 员工工作台骨架、Key 状态、安全中心和空的用量页面。
- PostgreSQL、Redis、对象存储、密钥管理与迁移框架。
- 员工唯一全能力 Key 的创建、摘要存储、显示一次、轮换和撤销。

退出条件：一名员工可以注册、登录、获得唯一有效 Key、轮换 Key；停用后所有请求都被拒绝。

## 5. 阶段 2：中转站接入与AI OPS目录

目标：让管理员接入多个已授权中转站，并以后台任务生成AI OPS的真实能力和内部路由目录。

交付物：

- Provider、ProviderModel、UnifiedModel、UnifiedRoute 和 HealthSample 数据模型。
- 受控凭据存储、主机白名单、适配器框架和中转站连接验证。
- 异步模型同步、能力探测、目录发布版本和最后成功快照。
- 管理员中转站页、模型映射页、路由配置页和健康状态页。
- 模型列表 API，只返回 active 的 ai-ops 及其当前能力。

退出条件：至少两个中转站可同步不同或重叠原始模型；员工模型列表只显示AI OPS，不暴露上游名称，目录请求不依赖实时上游调用。

## 6. 阶段 3：文本与代码数据网关

目标：建立低延迟、可回退、可流式的核心调用链路。

交付物：

- /v1/models、/v1/responses 和 Chat Completions 兼容入口。
- Key 鉴权、速率限制、模型能力校验、请求追踪和异步计量。
- 平台级会话持久化、跨路由上下文重建、流式检查点与恢复。
- 路由评分、候选选择、每模型熔断、同模型回退和连接池。
- SSE 透传、取消链路、可控重试和错误归一化。
- 路由、TTFT、成功率、429、用量和成本观测面板。

退出条件：AI OPS文本请求在上游站点故障时能按策略回退；流式首 Token 不被完整响应或同步日志阻塞；会话和路由决策可从 request_id 追溯。

## 7. 阶段 4：图片、视频与音频

目标：让同一 Key 支持多模态，同时不牺牲文本路径的低延迟。

交付物：

- 受控文件上传、对象存储隔离、恶意文件扫描和资产访问策略。
- 图片生成和编辑适配器、短任务与 job 统一状态。
- 视频 job、专属队列、预算预占、上游回调或自适应轮询、取消和结果交付。
- 音频能力按目录接入，支持同步或异步模式。
- 媒体工作台、我的任务、预览、下载和失败重试体验。

退出条件：视频提交快速返回 job_id；文本服务不因视频队列积压而显著降级；作业重启、回调重复和取消可正确恢复。

## 8. 阶段 5：Codex 与 WorkBuddy 一键接入

目标：员工无需手工复制复杂配置。

交付物：

- AI OPS Connect 安装器、签名更新、设备授权和系统凭据库存储。
- Codex provider 配置适配、备份、回滚、令牌命令和连通性测试。
- WorkBuddy 版本探测与官方能力优先的适配器。
- 员工门户的连接、重连、状态、撤销和错误说明。
- 客户端兼容矩阵与自动化回归用例。

退出条件：安装连接器后，员工可在门户一键连接已支持版本的 Codex 和 WorkBuddy；Key 轮换、设备撤销和配置升级可验证生效。

## 9. 阶段 6：压测、安全与生产上线

目标：证明系统在真实多站点、多员工、多模态流量下可靠、安全、可恢复。

交付物：

- 文本并发、TTFT、路由回退、熔断和恢复压测。
- 图片、视频、音频队列、预算预占、回调重复和大文件测试。
- 密钥、权限、SSRF、上传、会话、审计和灾难恢复安全测试。
- 数据备份、恢复演练、监控告警、值班 runbook 和发布回滚方案。
- 生产环境的区域部署、域名、TLS、密钥管理、容量阈值和成本告警。

退出条件：通过 [验收标准](/delivery/acceptance) 中的所有 P0 条目，并完成一次真实的故障和恢复演练。

## 10. 依赖与决策门

| 决策门 | 需要的证据 | 不通过时的处理 |
| --- | --- | --- |
| 中转站合法接入 | 已授权凭据、协议和模型能力 | 不接入，不做绕过或账号共享 |
| WorkBuddy 连接器 | 目标版本的官方配置方式或可验证本地配置 | 降级为快速配置，不标记一键 |
| 视频模型接入 | 作业 API、查询、取消、成本和结果交付验证 | 暂停AI OPS的视频能力，不对员工开放 |
| 生产发布 | 压测、安全和恢复证据 | 保持灰度，不全量开放 |

## 11. 迁移要求

新旧系统短期并行时，必须使用清晰的网关域名、数据边界和路由开关。历史系统请求不能被悄悄重定向到新系统，也不能让新平台继承历史凭据或权限语义。完成迁移后，先撤销旧员工 Key，再关闭旧入口，最后按数据保留政策下线旧服务。
