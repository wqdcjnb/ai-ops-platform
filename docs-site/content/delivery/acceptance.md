# 验收标准

## 1. 验收原则

验收必须基于真实请求、真实中转站能力和可复现证据。页面上显示“已连接”、演示模型、模拟用量或硬编码成功状态均不构成验收。

当前版本上线前，标记为“当前”的 P0 项必须通过。涉及平台级设备令牌、跨设备会话恢复、媒体 job、对象存储、预算预占和熔断的条目是下一阶段 P0，不可因已写入本文档而被视为已交付。

## 2. 身份与权限

| 编号 | 级别 | 验收条件 |
| --- | --- | --- |
| ID-01 | P0 | 员工注册页要求真实姓名、唯一邮箱和密码；密码不以明文保存或回显 |
| ID-02 | P0 | 员工可只用邮箱和密码登录；无效凭据、限流和重置流程安全可用 |
| ID-03 | P0 | 超级管理员不能由公共注册页获得；员工不能访问管理员接口或数据 |
| ID-04 | P0 | 停用员工后，其 Key、会话和设备令牌无法创建新调用或新作业 |
| ID-05 | P1 | 员工可查看并撤销自己的设备、修改密码和注销其他会话 |

## 3. 统一 Key 与模型目录

| 编号 | 级别 | 验收条件 |
| --- | --- | --- |
| KEY-01 | P0 | 每名员工默认恰有一把有效全能力 Key；仅 Key 所有者在其已认证门户中可显示或复制当前值，管理员及其他员工只能得到掩码 |
| KEY-02 | P0 | 同一 Key 只调用AI OPS，即可使用其已启用的文本、图片、视频和音频能力，不需要不同上游 Key |
| KEY-03 | P0 | Key、密码、上游凭据不会出现在数据库普通查询字段、管理员响应、URL、浏览器持久化存储、日志或 Git；Key 的加密副本只供所有者已认证门户恢复当前值 |
| CAT-01 | P0 | 模型列表来自已发布的AI OPS目录快照，员工只看到 ai-ops，不能在员工请求时串行查询中转站 |
| CAT-02 | P0 | 员工模型列表不泄露中转站地址、上游 Key 或原始认证信息 |
| CAT-03 | P1 | 管理员可查看AI OPS每项能力的内部候选、兼容条件、健康度和路由范围；员工不可见原始模型 |

## 4. 多中转站与低延迟网关

| 编号 | 级别 | 验收条件 |
| --- | --- | --- |
| GW-01 | P0 | 至少两个已授权中转站可接入，目录同步和健康状态独立运行 |
| GW-02 | 当前 P0 | 健康过期时并发探测 2 至 8 个候选站点的 `/models`，首个成功者获胜；不进行全站串行探测 |
| GW-03 | P0 | 上游首个流式片段抵达后立即转发，日志和计量不会等待完整回复 |
| GW-04 | 下一阶段 P0 | 某一中转站或模型连续失败会熔断，其他健康路由仍可服务 |
| GW-05 | P0 | AI OPS只在满足当前请求能力、参数、工具和上下文契约的内部路由间回退；不会用不等价能力处理请求 |
| GW-06 | P1 | 管理员可查看 TTFT、成功率、限流率、在途请求和路由选择证据 |
| GW-07 | 当前 P0 | 取消的仅是并发 `/models` 健康探测；文本、图片、视频、语音的真实请求只提交给一个胜出站点 |

## 5. 会话连续性

| 编号 | 级别 | 验收条件 |
| --- | --- | --- |
| CONV-01 | 下一阶段 P0 | 用户输入在上游调用前耐久写入；流式输出有检查点，断网或进程重启后记录不丢失 |
| CONV-02 | 下一阶段 P0 | 员工轮换 Key、更新连接器、切换中转站或更换设备后，可在平台找到并续接自己的会话 |
| CONV-03 | 当前 P0 | 导入 Codex 或 WorkBuddy Provider 不删除其原有本地历史、配置或非 AI OPS 会话 |
| CONV-04 | 下一阶段 P0 | 路由切换后，会话服务按契约重建上下文；摘要、裁剪或失败均可追溯，不能静默丢失消息 |
| CONV-05 | 下一阶段 P1 | 已认证客户端版本可将本地线程映射到平台 conversation_id；不支持恢复的版本不可标记为已认证 |

## 6. 图片、视频与音频

| 编号 | 级别 | 验收条件 |
| --- | --- | --- |
| MM-01 | 当前 P0 | 同一 Key 通过 JSON 端点提交图片、视频和语音，并且只使用 ai-ops |
| MM-02 | 当前 P0 | 视频请求经选站后只提交一次，并保留上游同步结果或异步任务响应；平台尚不伪造 job_id |
| MM-03 | 下一阶段 P0 | 平台作业状态、失败、取消、回调重试和服务重启后恢复均正确且不重复计费 |
| MM-04 | 下一阶段 P0 | 上传与生成资产按员工隔离，下载链接短时有效，不可枚举 |
| MM-05 | 下一阶段 P0 | 视频和高成本图片在提交前预占额度，并发和预算不足时清晰拒绝 |
| MM-06 | 下一阶段 P1 | 文本高峰或视频队列积压不会使其他模态的健康服务显著下降 |
| MM-07 | 下一阶段 P1 | 媒体工作台展示安全、可理解的队列、进度、完成、失败和取消状态 |

## 7. 客户端一键接入

| 编号 | 级别 | 验收条件 |
| --- | --- | --- |
| CON-01 | 当前 P0 | 门户不把完整 Key 放入 URL、二维码、浏览器历史或持久化存储；仅 Key 所有者可在已认证门户中显示、复制并生成配置 |
| CON-02 | 当前 P0 | 本机连接器直接写入用户级 Codex 配置和 WorkBuddy `models.json`，两者均固定为网关和 ai-ops，不下载配置文件 |
| CON-03 | 当前 P0 | 导入说明要求合并 Provider 配置，不覆盖其他客户端设置或会话；Codex 检测登录状态但不读取 `auth.json` 或创建虚拟身份 |
| CON-04 | 下一阶段 P0 | 撤销设备后，该设备无法继续获取调用令牌；其他设备不受影响 |
| CON-05 | 当前 P0 | 本地客户端连接器只允许回环门户来源，保留其他模型，且不得读取或改写 Codex/WorkBuddy 身份与对话数据库 |
| CON-06 | 下一阶段 P1 | Key 轮换和网关配置升级后，连接器能安全恢复或给出明确修复提示 |
| CON-07 | 当前 P0 | Codex 自定义 Provider 使用 env_key 和 requires_openai_auth=false；无需使用 OpenAI / ChatGPT 身份认证 |

## 8. 安全、监控与恢复

| 编号 | 级别 | 验收条件 |
| --- | --- | --- |
| SEC-01 | P0 | 中转站凭据只由服务端密钥管理读取，浏览器无法获取 |
| SEC-02 | P0 | 网关拒绝未经授权模型、无效 Key、被停用员工、越权资产和超预算作业 |
| SEC-03 | P0 | 所有副作用请求支持幂等；网络重试不会重复创建视频或重复扣费 |
| SEC-04 | P0 | 管理关键动作、Key 轮换、设备授权、预算和中转站变更有审计记录；系统审计事件超过 30 天会自动清理，保留记录的哈希链校验仍通过 |
| SEC-05 | P0 | 具备中转站凭据泄露、Key 泄露、Redis 故障、对象存储故障和队列重启的处理预案 |
| OPS-01 | P1 | 监控能按中转站、模型、模态、员工和错误类查看指标 |
| OPS-02 | P1 | 完成备份恢复演练与一次熔断恢复演练 |

## 9. 证据格式

每项验收记录必须包含版本、环境、时间、操作者、前置条件、操作步骤、实际结果、request_id 或 job_id、截图或日志摘要，以及失败时的修复记录。证据中不得出现完整 Key、密码、上游凭据或员工媒体原文件。

## 10. 上线阻断条件

出现以下任一情况必须阻断上线：

- 员工可以看到或直接调用中转站地址与上游凭据。
- 全能力 Key 无法通过AI OPS访问已承诺的不同模态，或需要员工管理多把上游 Key。
- 对话记录因路由、配置更新、Key 轮换、断网或设备迁移而丢失。
- 视频任务会长期占用 HTTP 连接、无法查询状态或重复扣费。
- 某一中转站故障让所有模型不可用且没有熔断。
- 连接器把完整 Key 写入明文配置或无法按设备撤销。
- 管理权限、员工隔离、资产访问、预算预占或审计任一 P0 项失效。
