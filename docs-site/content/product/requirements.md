# 产品需求与边界

## 1. 产品定位

AI OPS 是组织内部的统一模型访问平台。它连接多个已授权的中转站，在后台归一化原始模型和调用协议，并向员工提供一个稳定的统一网关地址、一个全能力 Key 和唯一员工可见模型 AI OPS。

平台分为控制面和数据面：

- 控制面负责员工、权限、中转站、模型目录、路由策略、预算、设备和审计。
- 数据面负责实时鉴权、模型选择、请求转发、流式响应、JSON 多模态转发和使用量归集。自建异步媒体作业服务是后续扩展，不属于当前已交付接口。

## 2. 角色

| 角色 | 数量与来源 | 可以做什么 | 明确不能做什么 |
| --- | --- | --- | --- |
| 超级管理员 | 系统初始化时创建且仅保留一名有效主体 | 管理已注册员工、中转站、模型目录、全局策略、预算、审计和设备接入 | 不可创建员工账号、不可查看员工密码或上游明文凭据 |
| 员工 | 多名；通过注册页自行创建 | 登录、首次创建或重置自己的 Key、导入客户端配置、调用模型、查看自己的用量和任务 | 不可查看其他员工、上游站点或全局路由 |
| 系统服务 | 无人工登录 | 同步目录、探测健康、执行任务、计量与告警 | 不拥有人工管理员权限 |

超级管理员由受控初始化流程创建，不能从公共注册页获得。员工注册必填真实姓名、邮箱和密码；邮箱必须唯一。生产环境默认要求邮箱验证，账户验证完成后才可获取 Key 和调用能力。

## 3. 员工身份与登录

注册页字段：

| 字段 | 规则 |
| --- | --- |
| 真实姓名 | 2 至 64 个字符；用于人员归属、审计和管理展示 |
| 邮箱 | 唯一、标准格式、小写归一化；用于登录和验证 |
| 密码 | 最低长度、强度检查和泄露密码筛查；只保存不可逆密码摘要 |

登录只使用邮箱和密码。登录成功后使用安全会话 Cookie 或短生命周期访问令牌加旋转刷新机制。员工修改密码、重置密码、注销所有设备和 Key 轮换都必须留下安全事件。

## 4. 统一 Key 规则

每位员工默认最多只有一把有效的员工全能力 Key。该 Key 由员工在首次登录后主动创建，固定指向 AI OPS，不绑定某一个中转站或某一个原始模型。

| 规则 | 定义 |
| --- | --- |
| 可见性 | 已登录员工可在自己的门户显示、复制当前有效 Key；完整值绝不出现在管理员列表、管理员接口、URL、浏览器持久化存储或日志中 |
| 服务端存储 | 保存 Key 的不可逆摘要、掩码、状态、创建时间、最后使用信息与 AES-GCM 加密副本；加密副本只用于向已认证的 Key 所有者恢复当前值，管理员接口绝不返回完整 Key |
| 模型权限 | 默认可以调用 AI OPS 的全部 active 能力；超级管理员可整体暂停某种能力或 AI OPS |
| 轮换 | 员工自行重置或管理员主动重置后，旧 Key 立即撤销；新 Key 立即生效，并可由该员工在其已认证门户中显示、复制或导入 |
| 撤销 | 员工停用、异常风险或管理员手动操作都会立刻阻止新请求 |
| 计量 | 所有请求、作业和资产都关联 employee_id、key_id 和 request_id |

“全能力”指 AI OPS 的所有已启用能力，而不是无限消费。文本 Token、图片规格、视频秒数、并发和每日预算由组织级策略控制；策略不需要按员工手工逐模型配置。

## 5. 功能范围

### 5.1 中转站管理

超级管理员可以添加、验证、启用、停用和排序中转站账号。每个账号可暴露不同模型、协议、地域、价格和限额。管理员填写名称、Base URL 和 API Key 后，平台从该账号读取模型目录；模型默认全选，但管理员可逐项取消或一键全选。保存时服务端必须再次读取目录并拒绝未被当前账号实际返回的模型。员工请求到达时不得逐站查询或暴露模型选择过程。

### 5.2 AI OPS目录

后台目录只同步管理员为各中转站选择的原始模型，但员工模型列表只展示一项：AI OPS，API ID 固定为 ai-ops。AI OPS必须声明当前可用输入输出模态、支持的 API、限制和当前状态；原始模型、上游站点和内部路由不向员工公开。

### 5.3 文本与代码

支持统一 Responses 风格接口，并在需要兼容的客户端中提供 Chat Completions 适配。默认流式返回。AI OPS在后台只会选择满足当前请求模态、工具、上下文和规格条件的原始模型；员工无需选择或知晓该选择。

### 5.4 图片、视频与音频

当前同一 Key 可通过 `/v1/images/generations`、`/v1/videos` 和 `/v1/audio/speech` 调用已启用中转站的 JSON 兼容接口。它们和文本一样只接受 `ai-ops`，并使用同一套并发健康探测、单站真实提交和安全回退逻辑。

图片编辑 multipart、音频转写、上传资产、平台统一视频 job、回调、取消和结果托管不是当前接口的一部分。上游若已返回异步视频任务，网关保留该上游的任务语义；后续要提供平台级任务工作台时，必须以幂等 job 和独立队列实现，不能重复投递生成请求。

### 5.5 客户端一键接入

员工门户只保留一个“导入配置”按钮。员工创建 Key 后，或在后续任何已登录门户会话中，均可显示或复制自己的当前 Key，并由本机连接器直接更新 Codex 或 WorkBuddy 模型配置。员工不需要手动填写网关地址或模型名。

Codex 配置固定为 `ai-ops`、`requires_openai_auth = false` 和 AI OPS 自定义 Provider。连接器会检测 Codex 登录状态供员工确认，但未登录时仍可直接配置 AI OPS；不得创建、伪造或接管 OpenAI/ChatGPT 身份。连接器仅监听回环地址，原子更新用户级 `~/.codex/config.toml`、用户环境变量 `AI_OPS_TOKEN` 和 `~/.workbuddy/models.json` 中的 AI OPS 条目，并保留其他模型；导入是“新增或更新一个 Provider”的配置操作，不能删除或重置 Codex / WorkBuddy 原有对话记录。

### 5.6 会话连续性

当前接入保证是非破坏性的：导出或导入 Provider 配置只添加 AI OPS 自定义模型，不调用清理、迁移或重置任何 Codex / WorkBuddy 会话文件。内部中转站切换、健康探测、失败回退和 Key 轮换都发生在网关请求层，不会要求客户端创建新对话或丢弃本地历史。

平台保留调用审计与现有对话审计。若要把 AI OPS 升级为跨客户端、跨设备的会话权威存储，还需单独实现稳定会话 ID、完整 turn 持久化、断流检查点和客户端历史恢复协议；在这些能力完成前，不能把“审计日志”描述成完整的聊天备份。

## 6. 非功能要求

| 领域 | 最终要求 |
| --- | --- |
| 可用性 | 某中转站故障不得拖垮其他中转站和其他模态 |
| 低延迟 | 健康过期时并发探测 2 至 8 个候选站点，首个成功者获胜并取消其余探测；真实请求绝不并发重复提交 |
| 可扩展性 | 新中转站以适配器方式接入，不修改员工客户端 |
| 可观测性 | 每次请求和作业都可追踪路由、耗时、重试、费用和结果状态 |
| 审计保留 | 系统审计日志最多保留 30 天；启动和每小时任务自动清理到期事件，保留部分重建哈希链。人员与 Key 的删除状态不依赖可过期审计日志 |
| 安全 | 上游凭据服务端加密保存；Key、密码和设备令牌不写入普通日志 |
| 可恢复性 | 作业、目录同步、计量和会话写入具有幂等性；系统重启后可恢复状态和会话记录 |

## 7. 术语

| 术语 | 含义 |
| --- | --- |
| 中转站 | 组织已授权连接的上游模型服务，不等于员工账号 |
| AI OPS | AI OPS 唯一暴露给员工和客户端的自定义虚拟模型，API ID 为 ai-ops |
| 路由 | AI OPS按请求能力映射到一个或多个中转站原始模型的可执行规则 |
| 全能力 Key | 员工唯一 API Key，可调用 AI OPS 的所有已启用能力 |
| 导入配置 | 本机连接器直接写入 Codex / WorkBuddy 的 AI OPS 模型配置 |
| 本地连接器 | 回环受控工具，用于直接写入或更新 Codex / WorkBuddy 配置，不读取或改写身份、对话数据库 |
| 媒体作业 | 图片、视频、音频等可能长时间执行的异步工作单元；平台级 job 服务尚属后续扩展 |
