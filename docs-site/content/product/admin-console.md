# 超级管理员控制台

超级管理员控制台是控制面，不提供“统一入口”首页。管理员管理的是组织的模型服务能力和已注册员工，不是个人账户资源，也不替员工创建账号。

## 1. 信息架构

~~~text
人员信息管理
├─ 模型目录
├─ 第三方账号
├─ 模型调用分析
├─ 审计日志
└─ 对话审计
~~~

## 2. 人员信息管理

员工只能通过员工注册页自行创建。管理员页面不得出现“添加人员”“批量导入人员”或“创建 Key”功能。

人员信息管理将原来的人员和 Key 列表合并为一张表，字段固定为：

| 人员 | 状态 | API 密钥 | 创建时间 | 最后使用 | 操作 |
| --- | --- | --- | --- | --- | --- |
| 真实姓名与登录邮箱 | 启用或停用 | 仅显示 Key 掩码 | 账户创建时间 | Key 最近一次成功调用 | 三点菜单：启用/停用、删除、重置密码、重置 Key |

操作规则：

- 重置密码固定为 `123456`，服务端只记录“已重置”，不得将该值写入审计正文、日志或浏览器持久化存储；页面必须提示员工首次登录后修改。
- 重置 Key 必须立即吊销旧 Key，并立刻更新列表内的掩码；管理员不能查看完整新 Key。员工下一次进入自己的门户后可显示、复制或导入当前 Key。
- 停用员工必须同时阻止其 Key 和设备令牌的新请求；删除只允许在停用后执行。删除状态独立于审计日志持久保存，系统审计元数据最多保留 30 天。

## 3. 第三方账号（中转站）管理

“第三方账号”是本控制台的重点模块。每一条记录代表一个已授权中转站账号，不代表员工账号、Codex 账号或单个模型。

管理员创建或编辑第三方账号时只输入显示名、Base URL 和上游 API Key；凭据只通过服务端验证并加密保存。点击“获取模型列表”后，系统读取该账号可用模型并默认全选；管理员可一键全选、取消全选或逐项调整接入范围。保存时服务端重新读取目录，确保所选模型仍由该账号实际返回。

接入面板提供“测试已选模型”：每个模型展示可调用、目录已确认或不可用状态及延迟。测试仅在管理员主动点击时向文本候选发出最小文本探测，先试 Chat Completions，未提供该端点时再试 Responses；目录元数据或保守模型名识别出的图片、视频、语音模型不会自动创建可能计费的生成任务，而是保留“目录已确认”并只进入对应专用接口的内部候选集。列表展示账号名称、受控服务地址、已选模型数、启用状态、健康状态、最近探测延迟、最后同步、最近错误摘要以及编辑、健康检查、同步、启用/停用、删除操作。健康检查只读取该账号的 `/models`；同步应使用已加密保存的凭据，不要求管理员每次重新输入 Key。

## 4. 模型目录

模型目录可复用通用目录页面样式，但数据只来自第三方账号的同步快照。它不读取或复用任何已下线控制面的数据。

同一个原始模型名出现在多个中转站时，目录只能展示一行，并在“来源中转站”列显示全部来源标签。管理员可按模型名或来源筛选；“输入能力”在未可靠探测时不显示、不猜测。

员工、Codex 和 WorkBuddy 不从该目录选择模型，统一只使用 `ai-ops`。

## 5. 中转站健康与后续性能分析

管理员为每个中转站维护显示名称、服务地址、认证凭据和启用状态。保存后由服务端验证连接并同步模型，而不是把凭据回传浏览器。

中转站详情必须显示：

- 连接和认证状态、最后成功同步时间、最近错误。
- 已发现模型数、最后一次轻量检查延迟与最后同步结果。
- 当前启用状态、认证失败或目录同步错误摘要。
- 后续“模型调用分析”可以补充每个站点的首 Token 延迟、完整耗时、成功率、限流率、在途请求数和成本；这些指标不影响当前第三方账号页面的安全凭据边界。

## 6. AI OPS与内部路由

当前网关把所有启用第三方账号同步到的上游模型作为唯一AI OPS的内部候选，员工端只发布 `ai-ops` 一项；目录项必须由实际验证结果生成，不能手工虚构“可用”。网关会并发探测有上限的候选站点，并仅向胜出站点提交一次真实请求。

管理员可执行：

- 查看模型目录、来源中转站、健康检查结果和调用审计。
- 启用或停用某个第三方账号，使其全部上游模型进入或退出AI OPS候选集。
- 后续增加按模态的手工策略前，不能在页面上假装存在主路由、备用路由或未经验证的能力开关。

## 7. 用量、预算与成本

预算在组织层设定，按文本 Token、图片规格、视频秒数、音频时长、并发和每天任务数执行。员工拥有全模型权限不意味着绕过预算。

控制台应提供：

- 组织总用量、按员工、模型、模态和中转站的分解。
- 预估成本与上游实际账单差异。
- 视频和高分辨率图片的额度预占、释放和失败退款记录。
- 阈值告警、单中转站异常激增、短时错误率上升和可疑 Key 使用提醒。

## 8. 审计

管理员关键动作必须可追溯：中转站变更、模型发布、路由策略变更、员工停用、Key 轮换、设备撤销、预算修改、作业取消和敏感导出。

管理审计默认只保存元数据，服务端在启动时及随后每小时清理超过 30 天的记录，并对保留部分重建本地哈希链。员工会话审计与系统审计分开管理，正文按其独立保留策略清理；管理员查看会话内容必须具有明确的受控授权、访问审计和数据保留依据。媒体资产仍按独立保留期处理，不能因会话存在就永久保存。
