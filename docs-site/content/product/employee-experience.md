# 员工门户与导入配置

## 1. 员工只面对一个模型和一把 Key

员工门户不会显示中转站、原始模型或供应商凭据。员工登录后只需要看到：

~~~text
我的账户
├─ AI OPS（ai-ops）
├─ 我的平台 Key
└─ 导入配置（Codex / WorkBuddy）
~~~

同一把平台 Key 可用于文本、代码、图片、视频和语音的已启用接口。实际中转站与原始模型由网关在后台选择；员工永远不需要切换或比较它们。

## 2. 注册、登录与 Key 生命周期

1. 员工在注册页填写真实姓名、邮箱和密码。
2. 系统以邮箱和密码登录；管理员界面没有“新增员工”入口。
3. 第一次进入员工门户时，员工主动点击“创建 Key”。
4. 创建完成后，员工可在自己的已登录门户中显示或复制当前 Key，并同时查看 Key 掩码、创建时间和最后使用时间。
5. 员工后续可以主动“重置 Key”；旧 Key 立即失效，新 Key 成为其门户可显示、复制和导入的当前 Key。
6. 超级管理员也可重置某员工 Key，但管理员列表只显示掩码，绝不会返回完整新 Key。

完整 Key 不进入 URL、浏览器历史、localStorage 或普通日志。服务端以加密副本保存它，只会在该 Key 所有者的已认证门户响应中返回；管理员和其他员工始终只能看到掩码。

## 3. 导入配置

Key 刚创建或重置完成后，员工可点击唯一的“导入配置”按钮，并选择目标客户端：

| 目标 | 当前导入结果 | 固定模型 | 认证边界 |
| --- | --- | --- | --- |
| Codex | 本机连接器直接更新用户级 `~/.codex/config.toml` 和用户环境变量 `AI_OPS_TOKEN` | `ai-ops` | 先检测登录状态；`requires_openai_auth = false`，不创建虚拟身份 |
| WorkBuddy | 由本机 AI OPS 连接器直接写入 `~/.workbuddy/models.json` | `ai-ops` | 配置只指向 AI OPS 网关，不暴露中转站凭据 |

员工点击 Codex 或 WorkBuddy 后，页面仅向本机回环连接器发送当前 Key 和网关地址；连接器以原子方式新增或更新 `AI OPS` 条目，保留其他自定义模型和全部对话数据库。Codex 会先显示本机登录状态：即使未登录，AI OPS 仍使用员工自己的平台 Key；连接器不会读取或改写 Codex `auth.json`，更不会创建虚拟 OpenAI/ChatGPT 身份。若本机连接器未运行，页面明确报错，不伪装成“已经导入”。

员工以后重新登录也可以显示、复制当前 Key 或重新配置客户端；不需要为了再次导入而无谓轮换 Key。管理员不能借此看到 Key，也不能从人员管理接口取得完整值。

## 4. 对话记录不丢失

导入动作是**新增 AI OPS Provider**，不会执行删除、迁移、清空或重置 Codex / WorkBuddy 的既有配置和对话文件。因此：

- 原有 Codex / WorkBuddy 对话会留在原客户端中。
- 已存在的对话可以继续使用；切换到 AI OPS Provider 不要求清除历史。
- 内部中转站切换、健康探测、失败回退和 Key 轮换发生在网关层，不会主动修改客户端的会话记录。

客户端本身能否把某一既有线程继续发往新的 Provider，仍由该客户端版本的线程/Provider 兼容能力决定。平台不把当前的调用审计误称为完整跨设备聊天备份；跨设备会话恢复需要独立的会话同步能力。

## 5. 多模态使用边界

员工使用同一 Key 调用统一网关：

| 能力 | 当前入口 | 说明 |
| --- | --- | --- |
| 对话、代码 | `/v1/chat/completions`、`/v1/responses` | 支持 OpenAI 兼容调用和流式响应 |
| 图片 | `/v1/images/generations` | JSON 图片生成请求 |
| 视频 | `/v1/videos` | JSON 视频请求，保留上游同步或任务响应语义 |
| 语音 | `/v1/audio/speech` | JSON 语音合成请求 |

Codex 最适合文本、代码和工具调用。WorkBuddy 可使用其支持的 OpenAI 兼容能力。图片、视频和语音是否有客户端界面由客户端自身决定；即使客户端没有专用按钮，标准 API 仍可使用同一 Key。图片编辑上传、音频转写、平台视频任务看板和大文件资产管理将在独立媒体作业服务中提供。

## 6. 员工看不到的内容

员工门户不显示：

- 上游中转站名称、地址、原始模型或路由排序。
- 任何上游 API Key、其他员工资料或管理员的操作记录。
- 本人完整 Key 的历史值或已经失效的 Key。

员工遇到网关容量不足或上游暂不可用时，只看到安全、可操作的错误信息和请求标识；不返回中转站认证头、供应商原始报错或内部路由细节。
