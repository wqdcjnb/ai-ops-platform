# 09｜日常操作手册

## 适用对象

本手册只给超级管理员使用。当前系统没有员工客户端，员工不登录 AI OPS；管理员在 AI OPS 创建并分发 New API Key。

日常操作不需要打开 CPA 或 New API 管理网站。只有 Codex OAuth 必须授权时，才按页面提示短暂打开官方授权页面。

## 1. 每次启动

在项目根目录执行：

```powershell
docker compose up -d
docker compose ps
Invoke-RestMethod http://127.0.0.1:4175/health
Invoke-RestMethod http://127.0.0.1:4175/api/platform/status
```

打开 AI OPS，先检查：

- 超级管理员登录正常。
- CPA 状态是否 ready。
- New API 渠道是否可用。
- 人员同步时间是否正常。
- 审计存储和清理任务是否正常。

如果服务不健康，不要先创建 Key；先看对应容器日志。

## 2. CPA 登录和状态

进入 AI OPS 的 CPA 页面：

1. 查看认证账号。
2. 查看模型列表。
3. 查看真实额度窗口。
4. 如果状态是 auth_required，点击“开始 Codex 登录”。
5. 只在 OAuth 必要时打开官方授权页面。
6. 回到 AI OPS，等待状态变为 ready。
7. 如果额度接口暂不可用，接受“未知”状态，不手工填数字。

不要：

- 在 CPA 管理网站手工创建账号。
- 将 CPA management key 复制给员工。
- 将 CPA 客户端 Key 当作员工 Key。
- 用本地调用次数替代 CPA 真实额度。

## 3. 同步 CPA 渠道

在 AI OPS 的渠道页面：

1. 查看 CPA 模型。
2. 查看当前 New API 渠道。
3. 点击预览同步。
4. 确认目标是唯一的 ai-ops CPA 渠道。
5. 点击同步。
6. 刷新并确认渠道状态、模型和时间。
7. 如果出现多个候选，停止操作并让开发者处理 marker，不要凭名称猜一个。

日常重复同步应是安全的，不应产生第二个渠道。

## 4. 导入人员

在 AI OPS 人员页面：

1. 点击从 New API 同步/预览。
2. 查看新增、更新、停用和缺失数量。
3. 确认人员字段为 id、用户名/姓名、状态、创建时间、最后使用时间。
4. 确认已停用人员不能创建 Key。
5. 确认预览无误后执行同步。

查询失败时不要执行批量停用。等待 New API 恢复后重新同步。

## 5. 创建和分发 Key

为员工创建 Key：

1. 选择一个 active 人员。
2. 选择一个 CPA 实际可用模型。
3. 确认一个 Key 只绑定一个人员和一个模型。
4. 确认额度为无限、有效期为永不过期、没有分组。
5. 点击创建。
6. 将一次性明文 Key 复制给员工。
7. 提醒员工安全保存，不要在聊天群或工单中公开。
8. 离开页面后不要期待再次看到完整 Key。

同一个人需要另一个模型时，创建新的 Key；不要把第二个模型追加到旧 Key。

如果 Key 创建失败：

- 查看页面 request_id。
- 查询 New API 是否实际已经创建。
- 若已创建但 AI OPS 未保存，先禁用孤立 Key，再重试。
- 不要连续点击造成多个 Key。

## 6. 按 Key 查看对话审计

进入审计页面，先选择 Key，再查看请求：

- 确认人员和模型与该 Key 一致。
- 查看真实 Prompt 正文。
- 查看真实回复正文。
- 查看流式、失败、取消状态。
- 查看 request_id、时间和保留到期时间。
- 只在需要时复制或导出。

复制/导出时：

- 确认自己是超级管理员。
- 选择最小时间范围。
- 不把导出文件放入公共目录。
- 用完后删除本地临时文件。
- 不在普通日志中记录正文。

超过 30 天的记录按页面显示“已过期”，不能要求系统伪造恢复。

## 7. 停用员工

员工离职或暂停使用时：

1. 打开人员详情。
2. 确认人员 externalUserId。
3. 点击停用并确认。
4. 等待所有关联 Key 完成禁用。
5. 检查 active Key 数量为 0。
6. 使用旧 Key 做一次安全的拒绝测试。
7. 保留历史审计，不删除人员历史。

如果出现部分失败：

- 不要手动把已成功禁用的 Key 重新启用。
- 点击重试未完成项。
- 记录失败 Key ID 和 request_id。
- New API 不可达时等待恢复，不执行猜测性批量操作。

重新启用人员不会自动恢复旧 Key；需要创建新的 Key。

## 8. 日常停机和恢复

普通停机：

```powershell
docker compose stop
```

恢复：

```powershell
docker compose up -d
docker compose ps
```

不要日常使用：

```text
docker compose down -v
git reset --hard
git clean -fd
```

若必须迁移机器：

1. 先停写入口。
2. 备份 CPA auths、New API 数据和 AI OPS 数据。
3. 迁移同版本 Compose 配置。
4. 启动并检查健康状态。
5. 验证 CPA 认证、New API 渠道、人员、Key 和审计。
6. 再开放管理员操作。

## 9. 常见故障

| 现象 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| CPA auth_required | 从 AI OPS 发起 OAuth | 打开 CPA 网站手工改配置 |
| CPA unavailable | 查看 cpa 日志和 Compose 网络 | 手动填假额度 |
| New API 渠道不可用 | 检查 CPA ready 和渠道状态 | 重复创建同名渠道 |
| 人员列表为空 | 查看同步 request_id 和分页 | 把本地 demo 数据当真实人员 |
| Key 创建失败 | 查询 New API 是否已部分成功 | 连续点击创建 |
| Key 请求模型被拒绝 | 确认 Key 的单一模型绑定 | 给 Key 加第二个模型绕过限制 |
| 正文为空 | 查看审计采集器状态和 request_id | 用前端内容补写假正文 |
| 停用未完成 | 重试失败 Token | 批量重新启用全部 Key |
| 页面显示旧数据 | 查看 stale/sync 时间 | 直接删除本地缓存数据库 |

## 10. 每日检查清单

- [ ] Compose 服务健康。
- [ ] CPA 状态和模型来自真实上游。
- [ ] CPA 额度未知时没有显示假数字。
- [ ] New API 渠道唯一且可用。
- [ ] 人员同步没有异常。
- [ ] 没有 active 人员被误标 disabled。
- [ ] Key 创建、停用和模型限制正常。
- [ ] 审计正文仍按 Key 隔离。
- [ ] 30 天清理任务最近一次成功。
- [ ] 日志没有出现管理密钥、Key 明文、Prompt 或回复正文。
- [ ] AI OPS 仍是唯一日常操作入口。
