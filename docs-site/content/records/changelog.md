# 文档变更记录

## 2026-09-27：最终方案建立

- 明确平台采用多中转站统一模型网关。
- 明确一个超级管理员和多个员工；员工使用真实姓名、邮箱和密码注册登录。
- 明确每位员工默认一个全能力 Key，只调用唯一自定义模型AI OPS；AI OPS在后台混合使用已启用的文本、代码、图片、视频和音频原始模型。
- 增加中转站目录同步、AI OPS内部路由、健康度、回退和低延迟设计。
- 已实现有上限的多站并发 `/models` 探测：首个健康响应获胜、其余探测取消，真实请求只提交给一个中转站。
- 已实现图片、视频、语音的 JSON 网关入口，并复用同一 Key、AI OPS和选站逻辑；平台级媒体作业、资产存储和队列留作后续扩展。
- 已实现 Codex 与 WorkBuddy 的本机回环连接器直接接入：Codex 原子更新用户级配置与 `AI_OPS_TOKEN`，WorkBuddy 原子更新模型配置；均不读取身份文件或改写对话数据库。
- 明确导入配置不删除客户端对话；完整跨设备会话恢复需要独立会话同步能力，不能用现有审计日志替代。
- 增加 Codex 无 OpenAI/ChatGPT 账号的自定义 Provider 接入要求与验收边界。
- 移除已下线控制面、旧凭据模式、单模型 Key 与仅管理员模式文档。

## 2026-09-27：界面与权限基线补充

- 删除管理员端“统一入口”；人员、部门与 Key 列表合并为“人员信息管理”。
- 管理员不能创建或批量导入员工账号；员工只能自行注册。
- 员工首次登录后主动创建唯一 Key，之后可自行重置 Key，并通过一个“导入配置”入口接入 Codex 或 WorkBuddy。
- 管理员人员操作固定为启用、停用、删除、重置密码（`123456`）和重置 Key；管理员列表永不显示完整 Key。
- “第三方模型”改为“第三方账号”：一个账号同步全部模型；模型目录按模型名合并多中转站来源，不显示未经验证的输入能力。
- 第三方账号增加独立健康检查、延迟记录、最后检查和最后同步时间；检查只读取模型目录，不触发生成请求。

## 2026-09-27：第三方账号接入与模型验证补充

- 接入面板改为只填写名称、Base URL 和 API Key，不再要求管理员手工提供账号标识。
- 管理员先获取模型列表；模型默认全选，可一键全选、取消全选或逐项选择，保存时服务端再次校验选择项。
- 增加已选模型测试，展示可调用、目录已确认、不可用及延迟；只有管理员主动执行测试时才发送最小文本探测。

## 2026-09-27：WorkBuddy 直接接入

- WorkBuddy 导入不再下载 JSON；员工门户调用本机回环连接器，直接更新 `.workbuddy/models.json` 中的 AI OPS 条目。
- 连接器仅监听 `127.0.0.1`、限制允许的门户来源、原子写入并备份现有活动配置；不读取或改写 WorkBuddy 对话数据库。
- 修正 WorkBuddy 模型 ID 为唯一公开模型 `ai-ops`，不再写入历史上游或旧模型 ID。

## 2026-09-27：Codex 直接接入与对话审计重试去重

- Codex 导入不再下载 TOML；本机连接器先检测登录状态，再直接写入 AI OPS Provider 和用户环境变量，保留原有配置备份。
- 未登录 Codex 时仍可配置独立 AI OPS Provider；系统不读取 `auth.json`，不创建或伪造 OpenAI/ChatGPT 身份。
- 对话审计为相同员工 Key、模型、接口和内容的 15 秒内重试保留首条记录，避免同一次客户端重发在列表中出现多条记录。

## 2026-09-27：审计数据保留与历史清理

- 系统审计日志改为最多保留 30 天：服务端启动时及之后每小时清理到期事件，并重建保留记录的本地 SQLite 哈希链。
- 人员与 Key 的删除状态迁移为独立持久状态，不再依赖可到期的审计事件。
- 根据管理员要求，清理 2026-09-27（北京时间）之前的本地对话审计记录，并清空当时已有的系统审计日志。
- 客户端标记为 `isNewTopic: true` 且附带 `title` 的内部标题生成请求不再写入对话审计；其正常调用计量不受影响。
- 管理员对话审计通过同一 `request_id` 关联网关用量，显示实际命中的上游模型；员工侧与公开网关响应仍只显示 AI OPS。

后续任何需求变化必须更新本记录、相关产品或技术页面，以及验收标准；不得只修改页面原型而不更新方案基线。
