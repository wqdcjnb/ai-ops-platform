## 对话审计规则

- New API 调用日志保存人员、Key、模型、Token、费用、耗时、状态和请求 ID，不承担完整对话存储。
- 对话内容由独立采集层在转发时获取，并通过请求 ID 与 New API 日志关联；未提前采集的历史内容无法补录。
- 默认关闭内容采集。管理员只能为明确的人员、用途或 Key 开启，并设置采集范围和到期时间。
- 普通管理员查看调用元数据；只有超级管理员可以配置采集策略和查看脱敏内容。
- 完整输入、回答和工具调用加密独立保存；Authorization、Cookie、OAuth Token、API Key、原始文件和未脱敏客户信息不得入库。
- 每次查看、搜索、导出和删除对话都记录操作者、原因、时间、对象和来源地址。

## 业务模型分配

| 业务模型别名 | 典型用途 | 分配原则 |
| --- | --- | --- |
| ecommerce-copy | 商品标题、卖点、详情页 | 质量达标后优先低成本 |
| ecommerce-service | 客服回复 | 速度、稳定性优先 |
| ecommerce-translation | 多语言翻译 | 术语一致性优先 |
| ecommerce-analysis | 销售与广告分析 | 复杂推理和数据能力优先 |
| ecommerce-coding | 脚本、自动化 | 工具调用与长任务能力优先 |

模型别名通过网关映射；名称不证明员工真实用途，必要时用独立 Key 或业务应用约束用途。图片、音频等能力另行配置支持的渠道。

## 额度规则

为人员设置相同初始预算，允许管理员按岗位调整。员工预算与上游账号剩余额度分别展示。平均分配由网关预算规则实现；轮询只分配请求，不能保证每人用量公平。

金额预算、Token 预算与上游订阅限额不是同一单位。订阅场景中的 Token 估价不得标为实际账单；并发请求的预算预留、取消结算和超限行为需实现并测试。

## 基础告警

一期包含预算 80%/100%、认证刷新失败、可用账号不足、错误率和流量突增。先在管理侧记录事件；企业微信或钉钉推送放入二期。
