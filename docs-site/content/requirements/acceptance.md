# 验收标准

## 1. 部署与管理员

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| DEP-01 | Docker 启动 | 一条 Compose 命令启动 AI OPS、New API、CPA；容器健康检查通过。 |
| DEP-02 | 管理员入口 | AI OPS 只有超级管理员管理会话；没有员工登录和员工客户端入口。 |
| DEP-03 | 凭据隔离 | New API 管理凭据、CPA 管理 Key、Codex OAuth 和完整 Key 不出现在浏览器响应、普通日志或 Git。 |
| DEP-04 | 故障状态 | New API/CPA 离线、超时、认证失败、额度不可读和字段不兼容都显示明确状态，不回退到演示数据。 |
| DEP-05 | 凭据分层 | CPA Codex OAuth、CPA 客户端 API Key、New API 渠道和员工最终接入 Key 能分别识别；CPA 渠道 Key 不会被误当作员工 Key 分发。 |
| DEP-06 | 统一启动 | 一条 Compose 启动命令拉起 AI OPS、New API、CPA；AI OPS 展示每个依赖的 health、版本、认证和同步状态。 |
| DEP-07 | 唯一入口 | 管理员只通过 AI OPS 完成日常操作；验收过程中不要求打开、登录或配置 New API/CPA 管理网站，前端不存在对应链接、iframe 或直连。 |
| DEP-08 | 重启恢复 | 停止并重启 New API/CPA 后，AI OPS 能显示 `degraded`/`starting`，恢复后自动或经一次幂等操作恢复渠道和状态，不产生重复渠道或 Token。 |

## 2. 人员目录

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| EMP-01 | 字段兼容 | 人员页展示 id、username、status、created_at、last_used_at 和管理操作列，字段与 New API 用户对象正确映射。 |
| EMP-02 | CSV 预检 | 能检查表头、必填字段、重复人员和非法值，错误行不写入。 |
| EMP-03 | 批量导入 | 成功导入人员同时出现在 AI OPS 和 New API 用户列表；初始密码不返回、不落 AI OPS 日志。 |
| EMP-04 | 停用联动 | 停用人员后，查询出的全部关联最终接入 Key 均被停用；部分失败显示失败清单。 |
| EMP-05 | 映射 | 人员与 New API `token_id` 的映射可追溯，刷新后不丢失。 |
| EMP-06 | 最后使用 | `last_used_at` 等于该人员关联 Key 的最新真实请求时间；无请求时显示为空。 |

## 3. CPA 模型和额度

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| CPA-01 | Codex 认证 | 沿用当前 CPA Codex OAuth 方案，认证状态和账号列表来自 CPA。 |
| CPA-02 | 模型目录 | 模型选项来自 CPA 当前真实模型接口，不显示本地演示模型或业务别名。 |
| CPA-03 | 路由校验 | 只有已配置到 New API CPA 渠道、实际可转发的 CPA 模型可以创建 Key。 |
| CPA-04 | 真实额度 | AI OPS 通过当前 CPA 管理适配读取真实额度窗口、剩余量和重置时间；当前接口不提供时显示未知，不从 OAuth 字段推算。 |
| CPA-05 | 凭据边界 | CPA 认证文件原文、refresh token 和 OAuth 响应不进入 AI OPS 页面、数据库或日志。 |

## 4. New API Key

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| API-01 | 创建 Key | 选择一个人员和一个模型后，AI OPS 服务端调用 New API 创建员工 Token/API Key；CPA 客户端 API Key 仅用于 New API 渠道。 |
| API-02 | 单人员 | 一个 Key 只能关联一个人员；一个人员可以有多个 Key。 |
| API-03 | 单模型 | 创建请求固定启用 New API 模型限制，限制恰好一个 CPA 真实模型；调用其他模型被 New API 拒绝。 |
| API-04 | 无限/永不过期 | 创建的 New API Token 使用无限额度和永不过期配置（按当前版本字段验证，目标为 `unlimited_quota=true`）；AI OPS 不自行扣减额度。 |
| API-05 | 不使用分组 | 创建和编辑界面不要求管理员选择或维护分组。 |
| API-06 | 一次性分发 | 完整员工 Key 只在创建/重新生成成功后显示一次；Key 列表、Key 管理导出和审计只显示掩码，正文导出按 AUD-08 单独受控。 |
| API-07 | 生命周期 | 停用、删除、重新生成后，New API 实际状态生效，旧 Key 不能继续调用。 |
| API-08 | 幂等 | 重复提交同一操作不会生成重复 Key 或重复执行破坏性变更。 |

## 5. 按 Key 的日志和对话审计

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| AUD-01 | Key 筛选 | 可以以内部 Key ID 作为第一筛选条件，并关联 New API Token ID、CPA 渠道 ID 查询真实请求记录。 |
| AUD-02 | 关系回溯 | 每条记录可以反查人员和绑定模型。 |
| AUD-03 | 元数据 | 至少展示时间、模型、状态、请求 ID、耗时和 Token 用量等真实元数据。 |
| AUD-04 | 时间线 | 可以查看同一 Key 的调用时间线，并跳转对应 New API 日志。 |
| AUD-05 | 真实正文 | 可以查看与该 Key/request_id 关联的真实 Prompt、上下文、工具调用和回复正文。 |
| AUD-06 | 流式与失败 | 普通、流式、失败和中断请求均能保存真实状态和已收到的正文片段。 |
| AUD-07 | 敏感内容 | Authorization Header、完整 Key、OAuth 和刷新令牌不进入正文存储或页面。 |
| AUD-08 | 查看/复制/导出审计 | 超级管理员查看、复制或导出正文的操作都会记录目标 Key、request_id、时间、原因和范围；导出不含凭据或认证 Header。 |
| AUD-09 | 生命周期 | 正文按不超过 30 天的保留策略加密保存，本版默认 30 天；到期可删除并产生删除证明。 |

## 6. 清理与事实源

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| SEC-01 | 事实源 | 删除 AI OPS 本地缓存后，重新从 New API/CPA 查询仍能恢复真实 Key、模型和额度状态。 |
| SEC-02 | 模拟数据 | 生产管理页面不显示旧 SQLite 演示人员、演示 Key、模拟额度、模拟调用或合成对话。 |
| SEC-03 | 旧功能隔离 | 被排除的本地网关、分组、路由、多角色和员工页面不出现在菜单，也不能通过公开接口绕过权限访问。 |
| SEC-04 | 审计 | 人员导入、Key 写操作、Key 查看/分发、人员停用、CPA 登录和同步失败均有管理员审计记录。 |
| SEC-05 | 失败一致性 | 上游写入失败时，AI OPS 不写入本地成功状态，不显示虚假的成功 Key。 |
| SEC-06 | 正文采集边界 | 若 New API 普通日志不提供正文，系统必须通过受控请求采集层取得真实内容，不得使用合成数据。 |
| SEC-07 | 统一适配器 | 浏览器不携带 New API/CPA 管理凭据；所有上游读写都经过 AI OPS 服务端适配器，并记录版本、同步时间和错误原因。 |
| SEC-08 | 无上游后台依赖 | 删除或屏蔽 New API/CPA 管理网站入口后，人员、渠道、Token、模型、额度和审计的核心流程仍可在 AI OPS 完成。 |

## 验收前必须确认

以下事项未确认时，只能完成接口探测，不能完成最终产品验收：

1. New API 当前部署版本的 Token 永不过期字段具体取值，以及停用/删除接口的版本差异。
2. New API 日志正文采集的具体改造点；普通日志没有正文时，必须在请求处理链路补齐真实 Prompt/回复采集。
