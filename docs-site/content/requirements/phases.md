# 实施范围

本项目先完成一个真实可用的单管理员统一控制台，再清理与目标无关的本地网关、演示数据和多角色功能。所有阶段都以 New API 和 CPA 的真实接口为验收依据，不以本地模拟数据代替。CPA 和 New API 随 Docker Compose 一起运行，管理员只操作 AI OPS；CPA 客户端 API Key 用于 New API 渠道，员工最终接入 Key 固定为 New API Token/API Key。

## 阶段 0：需求与接口冻结

- 明确 CPA Codex OAuth 账号、CPA 客户端 API Key、New API 渠道和 New API 员工 Token 是不同对象。
- 冻结员工最终分发 New API 用户 Token/API Key；CPA 客户端 API Key 永远只用于内部渠道，不能进入员工分发流程。
- 冻结 AI OPS 为唯一管理入口：不嵌入、不跳转、不链接 New API/CPA 管理网站；OAuth 官方授权如有需要只作为 AI OPS 发起的短暂外部授权流程。
- 固定 New API、CPA 镜像版本，记录 Token、模型、日志和 CPA 额度接口字段合约。
- 固定人员同步字段：id、username、status、created_at、last_used_at 和管理操作列。
- 确认 CPA 当前版本实际能否返回账号额度、重置时间和模型状态；当前部署已验证可由管理 `api-call` 代理读取 Codex usage/reset credits，需将其封装成版本适配器。
- 确定真实 Prompt/回复的采集位置：优先扩展 New API，必要时扩展 CPA 或保留受控审计代理。
- 固定正文加密、最多 30 天保留、到期删除、超级管理员查看/复制/导出和审计策略。
- 将旧页面和代码按“保留、改造、删除、暂缓”分类。

## 阶段 1：真实连接与人员目录

- Docker Compose 一次启动 AI OPS、New API、CPA，并等待依赖 healthcheck。
- AI OPS 服务端完成 New API 管理认证、CPA 管理认证、版本识别和健康检查；前端只显示统一状态。
- 通过 AI OPS 服务端适配器幂等校验/创建 New API 的 CPA 渠道，验证该渠道已使用 CPA 客户端 API Key；该 Key 不进入员工分发记录。
- 在 AI OPS 中提供连接、认证、同步和恢复状态；管理员不需要打开 New API/CPA 管理页面。
- 保留单一超级管理员会话，移除员工登录入口和多角色入口。
- CSV 导入、预检、搜索、编辑和停用人员，并同步调用 New API 创建/更新用户。
- New API 创建用户所需的初始密码由服务端随机生成，不展示、不写入 AI OPS 日志。
- 从关联最终接入 Key 的真实日志计算 last_used_at。
- 读取 CPA 真实认证账号、模型和额度摘要；接口不可读时展示明确状态，不从 OAuth 文件推算。

## 阶段 2：New API Key 管理闭环

- 通过 AI OPS 服务端读取 New API Token 列表、掩码、外部 ID、状态和模型限制，并保存 Token ID 映射。
- 从 CPA 读取模型，过滤出 New API 当前可路由的模型。
- 创建 Key：选择人员和一个模型，不选择分组。
- 固定单模型限制、无限额度和永不过期。
- 保存人员与 New API `token_id` 的本地映射。
- 支持查询、停用、删除、重新生成和一次性分发；所有写操作只由 AI OPS 服务端调用 New API，页面不直连上游。
- 人员停用时批量停用其全部关联最终接入 Key。
- 处理超时、认证失败、重复提交和字段不兼容。

## 阶段 3：真实日志、额度与按 Key 正文审计

- 读取 New API 真实日志和统计，按内部 Key ID 及可用的 Token/凭据 ID 归属人员。
- 在真实请求链路捕获 Prompt、上下文、工具调用和回复正文，关联内部 Key ID、可用的 token_id/凭据 ID 和 request_id。
- 处理普通响应、流式响应、失败响应和中断响应，保证正文与状态一致。
- 正文加密保存，只有超级管理员可查看、复制和导出；记录查看/复制/导出原因、时间和目标 Key。
- 正文最多保留 30 天，本版默认 30 天；执行到期删除和删除证明。
- 以 Key 为主筛选调用记录和真实对话正文。
- 从 CPA 展示 Codex 账号额度窗口、剩余量、重置时间和健康状态。
- 验证单模型限制、人员停用联动、Key 状态和 CPA 真实错误。
- 沿用当前 CPA Codex OAuth 登录认证，不改变登录入口。
- 补齐管理员操作和同步错误审计。
- 验证停止/重启 New API 或 CPA 后，AI OPS 能显示 `degraded`，恢复后自动重试或提供幂等重新同步，不生成重复渠道或重复 Token。

## 阶段 4：清理与发布

- 删除或隔离 AI OPS 本地 Key、额度、模型别名和演示数据链路；保留 New API 渠道所需的 CPA 客户端 API Key 配置，但不把它当员工 Key。
- 删除不用的本地路由、分组、上游和多角色页面；如果正文采集依赖本地 `/v1`，则将其收敛为受控透明审计代理而不是删除业务入口。
- 将页面、README、架构、安全、CPA 指南和测试文档统一到 V2.3 口径。
- 关闭对 New API/CPA 管理网站的业务链接、iframe 和前端直连；只保留 AI OPS 内的状态与操作。
- 固定 Docker 镜像版本，执行冷启动、停用联动、升级和恢复检查。

## 暂不纳入

- 员工客户端、员工登录、员工自助和通知分发。
- AI OPS 自建业务网关（仅保留为真实正文采集所需的受控透明入口）。
- 分组管理、用途路由、模型别名、备用模型和供应商切换。
- 本地额度扣减、周期重置、审批和并发预留。
- 其他模型供应商、其他 CPA Provider、官方 API 和 Ollama。
- 多管理员、部门负责人、财务角色和审批流。
- 内容质量分析和跨 Key 对话合并；第一版支持按 Key 的真实正文查看、复制/导出、脱敏和保留期管理。
